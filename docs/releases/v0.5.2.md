# TermRill v0.5.2 Preview

- Recover from a server's explicit generic POSIX rename failure when both the uploaded temporary file and the existing target retain their pre-request metadata.
- Use the existing backup, install, and rollback sequence for this guarded fallback in both upload paths. Never delete the original target before replacement.
- Stop on permission denial, transport errors, invalid responses, missing files, or changed metadata instead of attempting another replacement.

Metadata checks do not provide a transaction against other clients or detect content changes that preserve size and timestamps. Loopback regression coverage does not establish the cause of any particular Linux server rejection or replace macOS runtime acceptance.
