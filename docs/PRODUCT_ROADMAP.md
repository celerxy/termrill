# TermRill 产品需求与长期版本路线图

更新日期：2026-10-23

规划周期：未来约 60 个月（五年）  
状态：规划草案；近程范围可执行，中远程范围随用户反馈调整；AI 为正式规划方向，仍需按阶段验收。

## 1. 产品定位

TermRill 是面向开发者与小型运维团队的轻量 SSH/SFTP 桌面工作台。核心任务是安全连接服务器，可靠传输文件，高效浏览、预览与编辑文件，以及通过终端处理工作。

产品优先级：数据完整性 > 核心流程可靠性 > 操作效率 > 功能数量。保持本地优先；不把云账号、联网服务作为基本文件操作的前提。

### 目标用户与场景

| 用户             | 主要任务                             | 希望解决的问题                             |
| ---------------- | ------------------------------------ | ------------------------------------------ |
| 开发者           | 上传项目、修改配置、检查日志         | 在文件管理器、终端和编辑器之间频繁切换     |
| 运维人员         | 多服务器操作、恢复失败任务、批量处理 | 网络波动、任务状态不清楚、误覆盖风险       |
| 数据与内容工作者 | 查看图片、PDF、Notebook、压缩包      | 下载后才能查看、目录结构难以定位           |
| 小型团队         | 分享连接配置、遵循操作规范           | 配置分散、敏感信息分享不当、流程缺少一致性 |

### 暂不纳入核心定位

完整 IDE、远程 Notebook 执行平台、企业堡垒机替代品、云盘与备份平台不列入近程版本。AI、插件和团队云服务只有在核心体验稳定且需求成立后才进入开发。

## 2. 当前能力与真实缺口

| 能力       | 当前基础                                              | 后续重点                             |
| ---------- | ----------------------------------------------------- | ------------------------------------ |
| SSH 与认证 | 直连、标准跳板、指纹校验、多种认证、系统凭据库        | 实际环境兼容性与错误恢复             |

| 文档查看   | 文本编辑、Markdown、Notebook、图片、PDF、Mermaid      | 展示一致性、大文件性能、更多类型     |

| 桌面布局   | 双面板、终端、队列、紧凑工具栏                        | 更多 DPI、窗口与完整键盘验收         |

- **P0**：损坏文件、误覆盖、无法取消、状态失真、凭据泄露、无法连接等核心阻断问题。
- **P1**：高频效率需求，如收藏、导航、快捷键、搜索、可调布局。
- **P2**：专业工作流，如同步规则、日志、批量处理、差异查看。
- **P3**：扩展探索，如团队协作、插件、AI 辅助。

每项需求进入开发前应记录：用户场景、当前问题、范围、非目标、依赖、性能预算、失败与取消行为、验收条件。发现超出版本容量时拆到后续版本；安全和数据完整性问题优先修复，不等待功能版本。

## 5. 近期阶段的原始交付与验收要求

以下保留各需求阶段的范围和完成条件；其中已有实现，不应全部视为待开发清单，最新进展见第 3 节。

### v0.1.6：归档与界面收尾

**交付**

- 压缩包默认采用面包屑与当前目录列表，支持进入目录、返回上级和根目录。
- 识别没有显式目录条目的 ZIP，建立可浏览的虚拟父目录；虚拟目录不能作为未经转换的后端真实条目提交。
- 搜索覆盖全包，显示所在路径；明确搜索、分页、导航与跨目录选择的关系。
- 统一本地、远程、归档窗口的搜索焦点、菜单文案、禁用状态和空状态。
- 修复设置侧栏空白、窗口缩放遮挡、弹窗滚动及内容高度分配。

**验收**：有显式目录、无显式目录、空目录、深层目录、中文与长文件名均可浏览；选择操作与实际解压项目一致；常用窗口尺寸和显示缩放下不遮挡关键操作。

**依赖**：包内目录模型、原始路径映射、设计方案确认。缩略图可后置，不作为本版本完成条件。

### v0.1.7：可诊断性与体验基线

**交付**：统一错误分类与恢复建议；可复制经过脱敏的诊断信息；核心流程性能基线；建立功能支持矩阵与已知限制清单。

**验收**：认证失败、网络中断、权限不足、磁盘不足能区分；诊断不包含密码、令牌、私钥及文件正文；本地用户路径等信息需预览后选择是否导出。

### v0.2.0：可靠传输完善

**交付**

- 完善现有暂停、取消、重试、续传与任务持久化，不重新实现已有能力。
- 阶段区分扫描、数据传输、核对、安装与收尾；总量未知时不显示虚假的确定百分比。
- 展示耗时、平滑速度与剩余时间；不足以估算时显示未知。
- 断线后提供重新认证与恢复入口；可选自动重连必须可关闭、重试有上限。
- 主机指纹变化必须重新确认；多轮认证不能自动填答。
- 重启后列出可恢复任务，说明需要的连接及核对阶段；记录移除与临时文件清理状态分开说明。

**验收**：通过中断、重启、取消、源文件改变、同名冲突和安装失败等场景验收；不破坏已有目标；失败结果和临时文件状态可解释。

### v0.3.0：文件管理效率

**交付**：本地/远程目录收藏、最近访问、路径历史；可拖动调整面板与终端；快捷键和命令面板；批量重命名预览与冲突提示。

**验收**：远程收藏绑定连接配置；偏好可持久化；终端输入不被快捷键抢占；批量操作分项报告结果；布局有恢复默认入口。

### v0.4.0：同步与差异

**交付**：保存单向同步规则与排除项；快速比较和严格内容校验模式；文本差异查看；同步结果报告；可取消比较与同步。

**验收**：快速模式明确说明仅依赖元数据，不能保证内容一致；严格模式继续校验内容；覆盖前确认；默认不删除目标独有文件。自动定时同步与双向同步后置。

## 7. 正式版后的长期版本

### v1.1.0：项目工作空间

保存项目关联的连接、目录收藏、布局和非敏感偏好；提供最近项目与手动恢复工作空间。恢复不会自动执行命令、自动提交编辑内容或绕过认证。依赖 v1.0 配置迁移机制。

### v1.2.0：任务中心与可控自动化

统一传输、同步、压缩、搜索等任务的状态、排队、取消与结果。支持保存任务模板和用户主动开启的计划任务；清楚说明应用关闭、电脑休眠、认证过期时的行为。默认以应用运行期间执行为范围，后台服务另立需求。任务不能暗中扩大覆盖或删除权限。

### v1.3.0：编辑保护与恢复

完善远程编辑并发冲突检测，支持保存前差异预览及可选限量历史版本。探索软删除与回收站：仅对明确支持的文件系统/远程目录启用，容量、保留时间、真实占用与永久删除规则可配置。依赖安全路径处理及任务结果模型，不能假定所有服务器有回收站。

### v1.4.0：多平台与可访问性成熟

按实际使用需求完成 macOS/Linux 的原生安装、凭据库、键盘体验、系统字体与主题适配；增加深色模式、密度设置和完整键盘导航。发布范围按逐平台验收结果扩大，不先宣称全部平台成熟。

### v1.5.0：高级数据搬运

探索远程到远程传输、保存传输方案和带宽调度。优先提供明确标注的客户端中转，显示两端进度与本地资源占用；服务器直接互传单独评估权限、认证和协议条件。完善大量小文件任务表现与公平调度，保护现有任务恢复机制。

### v1.6.0：团队连接配置（需求成立后）

支持共享非敏感连接模板、环境分组与团队使用说明。第一步可采用文件导入导出；托管团队服务需单独批准部署、权限模型、运维成本与隐私范围。私人凭据始终独立；客户端记录不宣传为防篡改企业审计。

### v1.7.0：可选扩展接口（需求成立后）

定义有限的预览扩展与用户命令扩展接口；权限声明、安装确认、停用与卸载明确。先限定可审查的扩展范围，再考虑第三方插件生态。扩展不能默认获得所有连接凭据和文件读写权限。

### v1.8.0：智能辅助（可选）

可提供用户主动触发的错误解释、文本差异摘要与命令草稿。发送哪些内容、发送到哪个服务必须可见且经用户选择；命令与文件修改需确认后执行。先支持本地或自带服务配置，模型与费用单独展示。AI 不成为基本连接和传输的必需依赖。

### v1.9.0：大规模性能与企业场景评估

基于真实使用规模改进目录索引、任务调度、内存预算与多连接表现。评估企业代理、受限环境、部署策略和合规需求；厂商专用堡垒机兼容按独立集成项目处理，不以标准跳板能力替代承诺。

### v2.0.0：工作台整合

将经过验证的项目、任务、文件、终端与可选团队能力整合为一致工作台。只纳入有持续使用证据的模块；重大配置/API 变化必须有迁移路径。若扩展需求不足，保持 1.x 演进，无须为了版本号堆叠功能。

## 8. 性能与质量预算

以下是拟定验收目标，需要在 v0.1.7 建立参考机器、测试数据、网络延迟和测量方式后确认，不能视为当前性能承诺。

| 项目     | 拟定目标/约束                                                    |
| -------- | ---------------------------------------------------------------- |
| 列表交互 | 大目录不一次挂载全部行；参考环境下常规点击反馈目标不超过 100 ms  |
| 搜索     | UI 输入不阻塞；后台搜索可取消并有结果数量上限                    |
| 预览     | 大文件按需加载；PDF、图片、Notebook 缓存有预算和释放机制         |
| 任务进度 | 按固定节奏聚合更新，避免逐字节事件与无限日志                     |
| 内存     | 建立基线后给任务和缓存设上限；传输不随单个文件体积线性增长       |
| 启动     | 区分正式包与开发编译；冷启动、首次显示、首次可交互分别测量       |
| 网络     | 性能报告注明 RTT、带宽、文件数量和大小，不用单个速度承诺所有环境 |
| 稳定性   | 发布前执行长时间运行与中断恢复验收；时长与并发量写入具体版本计划 |

## 9. 通用发布验收

每个版本要求：

1. 核心路径有加载、空状态、错误、取消和完成表现。
2. 覆盖、删除、恢复和批量操作说明实际影响；不可逆操作有明确确认。
3. 不降低指纹验证、凭据保护、临时文件安装和恢复约束。
4. 通过适用的格式、类型、构建与用户授权的功能验证；记录未验证环境。
5. 提供实际窗口截图与目标设计的对比，不把编译成功当成视觉验收。
6. 更新支持矩阵、已知限制、版本说明与配置迁移说明。
7. 提交、标签和验收记录对应同一版本；发布及推送按用户授权执行。

版本类型：补丁版本修复问题与兼容缺陷；功能版本有明确主题；重大版本只用于产品整合或重大兼容变更。内部 milestone 标签不自动代表对外正式发布。

## 13. AI 产品定位与核心场景

AI 定位为文件与服务器工作流助手：帮助理解当前内容、形成方案，并在明确授权后调用受限工具。产品从读、建议、计划、执行逐级推进。

| 场景                   | 用户输入示例              | 产品行为                           | 结果与验收                               |
| ---------------------- | ------------------------- | ---------------------------------- | ---------------------------------------- |
| 错误解释               | 为什么这个上传失败了？    | 读取用户选中的脱敏任务错误与阶段   | 区分事实和猜测，提供可执行排查步骤       |
| 配置解读               | 解释这份配置每段的用途    | 读取当前文件明确选中的范围         | 引用行号；不把缺少环境证据的结论说成确定 |
| 日志诊断               | 帮我找这段日志的异常      | 分析指定时间范围与过滤结果         | 引用具体日志片段；限制上传内容量         |
| 代码理解               | 这个脚本会修改哪些文件？  | 只读选中脚本，解释副作用与条件     | 不自动运行脚本；无法判断时说明缺口       |
| Markdown/Notebook 辅助 | 总结这些单元的主要步骤    | 解析用户选中内容与可见输出         | 引用单元编号；不运行 Notebook            |
| 文件定位               | 找出最近改过的 nginx 配置 | 将请求转换为可预览的范围与过滤条件 | 优先确定性搜索；不让模型编造文件路径     |
| 命令草稿               | 给我查找占用端口的命令    | 结合已确认的系统信息生成草稿       | 展示目标、命令及副作用；默认不执行       |
| 文件修改               | 修改配置里的监听端口      | 形成文本补丁并校验基础语法         | 保存前展示差异；重新核对原文件版本       |
| 同步计划               | 把构建产物传到测试环境    | 解释来源、目标、排除规则与覆盖行为 | 进入真实传输预览；模型不伪造任务结果     |
| 运维排查               | 服务访问失败，帮我排查    | 先提出最小只读调查步骤             | 每步有实际证据；超出范围需要新授权       |
| 部署方案               | 部署这个项目到测试服务器  | 从已保存模板生成检查和执行顺序     | 明确停止条件、回滚限制与目标环境         |

AI 初期不做自主修复生产服务器、跨组织自动操作、后台扫描所有文件或无需确认的文件删除。

## 14. AI 能力分期与版本归属

### AI-0：基础准备（v1.1–v1.7 随基础版本推进）

**需求**：统一文件、任务和日志的只读上下文接口；选择范围与内容大小限制；脱敏预览；结果来源定位；权限模型与模型适配层设计。

**交付**：AI 功能开关、上下文选择器原型、工具能力清单、验收样例集。可以开发原型，但默认不开启数据外发，不阻塞当前基础版本。

### AI-1：只读理解（v1.8）

**需求**：选中文本解释、配置解读、错误分析、日志摘要、Markdown/Notebook 摘要。支持用户自配服务及经验证的本地服务；具体服务兼容列表以发布时实测为准。

**交付**：可停靠助手侧栏；显式“添加到上下文”；流式回复与取消；引用文件/行号/单元；发送前检查与脱敏预览。

**验收**：不主动上传整个目录；连接信息与凭据不进入模型上下文；网络失败可重试但不重复执行工具；读取不意味着获得写权限。

### AI-2：建议与草稿（v2.0–v2.1）

**需求**：自然语言文件搜索、命令草稿、配置补丁与差异摘要。

**交付**：建议卡片，提供复制、定位、打开差异和放入终端编辑区；传输、权限和文件修改必须进入已有确认流程。

**验收**：未知系统不生成假定兼容的执行命令；补丁不能覆盖已被其他操作修改的版本；拒绝模型自称执行成功。

### AI-3：计划与单服务器执行（v2.2–v2.3）

**需求**：将任务拆分为只读调查、文件变更、传输和命令执行步骤。

**交付**：执行计划、逐步确认、限时授权、暂停与停止、结果记录；默认单服务器、指定目录与明确任务范围。

**验收**：每步执行前检查连接、路径、权限与原文件版本；生产目标显示环境提示；取消后说明已完成影响；不宣称所有操作均可回滚。

### AI-4：模板与团队知识（v2.4–v2.6）

**需求**：结合项目运行手册、团队批准模板和历史任务结果，形成可重复的排查与部署方案。

**交付**：用户维护的项目知识库、来源引用、模板版本与批准状态、权限限制、缓存与索引清理。

**验收**：团队成员只能访问有权获取的资料；索引不携带凭据；过期说明书有提示；模板更新后重新评估执行权限。

### AI-5：多服务器协作（v3.0–v3.2）

**需求**：只读汇总多个已授权环境状态；用户审核后按小批次执行维护计划。

**交付**：目标矩阵、预检查、每台服务器独立结果、并发上限、失败停止阈值、人工继续入口。

**验收**：不能因一台服务器授权扩大到全部连接；失败不触发无限重试；高风险步骤仍逐批确认；网络分区下能识别结果未知状态。

### AI-6：主动提示与受约束自动化（v3.3–v4.0 候选）

**需求**：用户主动订阅的任务异常解释、日志模式提醒和维护建议；在预先批准的模板内运行有限自动化。

**交付**：触发条件、时间窗口、目标范围、预算、通知频率、失效时间和全局停止开关。

**验收**：默认关闭；不能借提醒扩大文件扫描范围；异常时停止而非自行更改保护规则；未授权的修改只生成待审计划。

## 16. AI 交互设计要求

### 助手入口

- 顶部助手按钮、文件/日志右键“添加到 AI 上下文”、选中文本解释入口。
- 使用可调整宽度的侧栏，不强制替换文件列表或遮挡终端。
- 当前上下文以卡片展示：文件名、来源连接、读取范围、内容大小、是否脱敏。
- 会话绑定项目或明确目标；切换服务器后保留上下文来源标识，不能混淆环境。

### 回复类型

| 类型     | 展示与操作                                         |
| -------- | -------------------------------------------------- |
| 解释     | 正文、来源引用、可展开依据与缺少信息               |
| 命令建议 | 目标环境、命令、说明、潜在影响；复制/编辑/明确执行 |
| 文件补丁 | 路径、基线版本、差异、语法检查结果；选择接受并保存 |
| 传输计划 | 来源、目标、覆盖规则、预计项目数量；进入原传输确认 |
| 多步任务 | 步骤列表、需批准步骤、运行状态、停止按钮与结果     |
| 诊断报告 | 症状、证据、假设、建议、已执行与未执行事项分开显示 |

### 不成功也能正常结束

取消模型生成仅停止回复；取消任务需另行停止工具执行。两者状态分别显示。模型断开时已完成文件操作仍记录，不能自动重做。结果长度超限、权限缺失、预算不足、上下文过大与服务不可用均提供清楚的退出路径。

## 17. AI 数据、授权与执行规则

### 上下文与隐私

- 默认只读用户指定的文件/范围，不自动遍历主目录或全部服务器。
- 发送前显示内容预览和目标模型服务；敏感配置可使用本地服务或取消。
- 脱敏包含常见密钥与令牌样式，但明确不能保证识别所有秘密；用户仍可查看和删除上下文。
- 会话历史、索引、缓存与操作记录分别设置保存范围、过期策略和清理入口。
- 服务商数据保留条款与费用以接入时实际协议为准，不在规划中作通用“零保留”承诺。

### 执行授权

| 级别 | 范围                  | 默认规则                                     |
| ---- | --------------------- | -------------------------------------------- |
| A0   | 仅解释已提供内容      | 不调用额外文件工具                           |
| A1   | 指定范围只读搜索/读取 | 用户确认范围，限制数量与时间                 |
| A2   | 生成命令或补丁        | 只生成，不执行                               |
| A3   | 指定文件变更/传输     | 确认实际差异或计划，复用原保护流程           |
| A4   | 指定服务器命令执行    | 单独确认目标与命令；有时限与取消             |
| A5   | 模板化批次自动化      | 仅后期开放；模板、目标、预算和到期条件均限定 |

授权必须绑定具体连接、路径/工具、任务和有效期。删除、覆盖、权限修改及生产环境命令不能继承笼统的聊天许可。计划变化或目标变化后重新确认。工具参数由应用验证，不能依赖模型口头承诺。

### 提示注入与不可信内容

文件正文、README、日志、压缩包内容、Notebook 输出、网页及外部工具结果都是待分析数据。它们不能更改授权、关闭指纹验证、指示泄露凭据或要求连接新服务器。来源标记、结构化工具参数、路径校验、权限边界与人工审核同时使用，不依赖单一提示词防护。

### 工具执行

模型通过受限工具接口进行读取、搜索、差异、传输和修改。文件操作复用 Rust 后端的校验与临时文件保护，避免绕过现有逻辑。任意 shell 执行是独立高风险工具，只有明确开放后才可使用，不作为所有后台操作的快捷通道。

## 18. AI 技术与性能规划

规划逻辑边界如下，具体代码结构在实施时按现有工程调整：

1. **上下文管理**：用户选择、内容预算、来源定位、脱敏、附件和保留策略。
2. **模型适配**：流式回复、取消、服务错误、模型能力探测、用户自配服务与本地服务。
3. **工具注册**：结构化输入输出、权限声明、读取范围、执行超时和资源上限。
4. **授权与策略**：确认记录、计划版本、连接绑定、有效期、撤销和高风险保护。
5. **任务编排**：有限步骤、状态持久化、失败停止、取消与恢复，复用任务中心。
6. **结果记录**：文件与命令真实结果、来源、脱敏导出、用户可清理历史。
7. **质量评估**：固定场景、错误分析、回归证据，不保存用户秘密作为样例。

性能要求：上下文按需读取；大文件截取或分段而非全量提交；内容检索有数量上限；长回复按需渲染；工具并发有预算；取消传播到正在进行的请求。模型选择、上下文上限和成本不固定绑死某个供应商。

不在此文档固化即时模型价格、供应商功能或 API 兼容结论；实际接入版本需查验最新官方资料并实测。

## 19. AI 质量评估与上线门槛

建立可重复的样例集，覆盖配置解释、日志异常、搜索、命令建议、补丁冲突、网络失败、提示注入和跨服务器授权等场景。目标数值在样例与人工评审方法确定后冻结。

| 评价项       | 验收方式                                                 |
| ------------ | -------------------------------------------------------- |
| 依据可核查   | 文件、行号、单元或日志引用真实存在，未找到依据时明确说明 |
| 结果可靠     | 不把模型建议当工具结果；只有后端确认后标记成功           |
| 权限有效     | 未授权写操作在工具层被拒绝，而不是仅在 UI 隐藏按钮       |
| 提示注入抵抗 | 恶意文件或日志不能扩大读取范围、导出凭据或执行命令       |
| 修改安全     | 版本冲突拒绝静默覆盖；补丁失败可解释；原文件保护验证通过 |
| 成本可控     | 达到预算停止新调用；取消后无持续无限工具循环             |
| 可退出       | 一键停止、撤销授权、关闭 AI 后核心功能继续可用           |
| 人工价值     | 典型任务完成步骤减少且错误没有增加；不只评价文字流畅度   |

上线方式：内部样例验收 → 可关闭的实验入口 → 用户主动启用的公开预览 → 稳定功能。读能力可先稳定发布，执行能力单独验收与放量。发现越权、秘密外发或损坏数据时关闭受影响执行入口，保留手动功能。

## 20. 长期需求池与产品组合

| 方向     | 可进一步规划的需求                                 | 推进条件                           |
| -------- | -------------------------------------------------- | ---------------------------------- |
| 文件体验 | 可选双栏对比、图片批量预览、目录统计、内容去重提示 | 大目录开销可控，先提示后操作       |
| 项目管理 | 环境标签、项目模板、常用目录与任务组合             | 配置结构和迁移成熟                 |
| 运维效率 | 端口转发管理、会话录制、本地命令模板、服务状态查看 | 明确授权、可清理记录、平台兼容验证 |
| 网络扩展 | 更丰富跳板链、代理和受限网络诊断                   | 有实际用户环境和验证条件           |
| 任务恢复 | 崩溃后恢复、结果未知核查、离线待办                 | 幂等与状态一致性设计成立           |
| 团队     | 配置模板、审批、项目知识、可选统一策略             | 独立组织身份与部署需求明确         |
| AI       | 只读解释、补丁建议、可审计划、单机和多机受控执行   | 逐级权限与质量门槛通过             |
| 扩展     | 预览插件、工具插件、模型适配、可选 MCP             | 权限边界与分发治理成熟             |
| 企业     | 自托管、策略分发、合规记录、受限环境安装           | 企业客户需求、成本和法律边界成立   |

可探索个人版、专业版及团队版组合，但核心文件安全、取消和恢复能力不作为付费限制。AI 费用由用户自配服务或明确计费方式承担；是否商业化及如何收费应另立决策文档，不在技术规划中直接定价。

## 21. 实施节奏、资源与决策关口

建议每次只推进一个主要功能主题，同时保留缺陷修复容量。拟定容量比例：核心需求约 60%，质量/性能/兼容约 25%，需求验证与探索约 15%；按实际团队规模调整。

| 关口           | 必须回答的问题                                         | 决策                           |
| -------------- | ------------------------------------------------------ | ------------------------------ |
| v1.0 前        | 手动核心流程是否稳定、恢复是否可信？                   | 未达标则推迟 AI 执行与团队扩展 |
| AI-1 前        | 上下文是否可控、引用是否真实、服务是否可取消？         | 只读能力试用                   |
| AI-3 前        | 权限是否由工具层强制、计划是否可审、取消是否有效？     | 单服务器小范围预览             |
| 团队服务前     | 需求是否持续、凭据隔离是否成立、谁维护服务？           | 先文件模板后可选服务           |
| 多服务器执行前 | 能否分项确认、限制批次、解释未知结果？                 | 严格限定目标试用               |
| v4.0 前        | 扩展使用是否持续、复杂度是否值得、迁移成本是否可接受？ | 决定整合或继续 3.x 演进        |

### 下一阶段文档拆分建议

在相应版本正式开工时新增独立需求文档，而非现在生成没有实现依据的详细设计：

- 归档导航 PRD：虚拟目录、搜索、选择和解压规则。
- 传输可靠性 PRD：恢复状态、失败分类、临时文件和结果一致性。
- AI 助手 PRD：上下文、回复卡片、引用与取消体验。
- AI 授权与工具规范：输入输出、路径范围、确认、超时及撤销。
- AI 评估计划：样例、评分、越权与失败场景、上线门槛。
- 团队与自托管需求：身份、权限、数据保留、部署与运营成本。
