# TermRill 架构导读

### 显式回环下载性能入口

`scripts/benchmark-transfer.py` 构建独立测试二进制，启动仅绑定回环地址的 fixture，交替运行生产原生下载与系统 OpenSSH SFTP。`transfer_benchmark.rs` 只作为 `reliability_tests` 子模块编译，普通应用不包含该入口；普通回归没有显式采样变量时不运行性能任务。入口明确调用 `connect_benchmark_native` 和 `execute_native_download`：测试兼容结构的 libssh2 Session 不连接网络，握手和正文均使用当前 russh 实现，不能改用旧测试基线的 execute_concurrent。两客户端都绑定启动器生成的预期公钥，认证前校验指纹；Windows 只收紧本次临时测试密钥 ACL，不修改用户密钥或 SSH 配置。

每次采样都恢复相同的 fixture 读取延迟，避免 Rust fixture 析构清理故障设置后改变下一客户端条件。生产传输、同名保护、临时安装与来源核对均复用现有实现；目标长度及 SHA256 由 Python 在采样计时外逐次检查。输出报告只包含枚举、版本、数字与摘要，失败不导出部分成功；原始进程日志只留在 ignored 本机结果目录。子进程超时关闭本次进程树，退出关闭 fixture，并在验证绝对目录边界后清理密钥和数据。人工场景标签不校验 TUN 状态；工具不接入真实服务器，也不改变生产并发、限速或停收隔离策略。

### EPUB 只读预览

`fileKind → RemoteDocumentDialog → MediaPreview → EpubPreview` 共用本地、远程及归档内二进制预览入口，保留 32 MiB 上限、读取进度、取消及连接所有权规则。`preview::validate` 对 ZIP 验证 EPUB mimetype；`unpack_epub` 通过 Tauri 二进制请求把已加载字节交给工作线程中的 `epub.rs`，不进行额外网络请求或磁盘解压。最多 4096 项、单项 8 MiB、总展开 64 MiB，声明和实际大小均检查，拒绝加密声明、重复文件、符号链接和不安全路径。返回包内资源的 Base64 映射；IPC 编码、原文件和解码缓冲分别占用内存。

`epubBook.ts` 解析 container/OPF、spine 与 EPUB 3 nav / EPUB 2 NCX，仅展示 spine 中的 XHTML。`epubPath.ts` 规范化相对引用并拒绝外链、协议、查询和包外路径。正文先移除原始属性，再为验证过的书内位图生成 Blob URL，以 DOMPurify 标签/属性白名单清洗；不加载原 CSS、字体、SVG、脚本或外部资源，不放宽 CSP。`EpubPreview` 维护章节、锚点、目录和字号；卸载丢弃过期解码结果并回收所有 Blob URL，不持久化书籍正文；阅读偏好按文末的本机阅读记忆规则保存。Rust 工作线程的容器展开有界执行，面板关闭不再接受其返回结果。

EPUB ZIP 资源路径先移除 `.` 和重复分隔符形成内存映射键，兼容 `./OEBPS/...`；拒绝绝对路径、父目录、反斜杠、冒号和控制字符。重复资源与加密声明检查均使用规范化路径，不能用等价路径绕过检查。此规则不修改磁盘解压、SFTP 或其他归档操作。

`EpubContents` 单独维护目录宽度与横向滚动，复用 `ResizeSeparator` 的指针捕获、取消和键盘行为；标题保持单行，左右按钮与 Shift＋滚轮只作用于目录视口。隐藏侧栏保留实例与位置，同时清理滚动监听和尺寸观察；显示时重新观察并更新可滚动状态，卸载时释放监听。

### 2026-10-23：普通下载停收与共享预算

`download_control.rs` 仅约束普通下载 READ：每秒观察所在连接收到的 DATA 正文，连续约 30 秒无增长时通过 `retire_download` 立即标记租约失效并关闭 SFTP 流。已失效连接不派发新范围、不回池，其在途只读范围可转交当前已验证且 OPEN/FSTAT 核对同一来源版本的存活句柄；每次失败转交必须排除原连接，因此不循环重连。全部连接失效返回错误，沿用连续前缀截断与临时文件安装规则。取消仍由 checked 响应；超过三秒未轮询的间隔不计网络停收，避免暂停、限速、写盘反压或运行时调度间隙触发误隔离。部分 DATA 或同连接其他 READ 的正文会重置等待，不将单个慢请求等同整条连接停收。此策略不扩展到预览、打包或上传。

Remote 持有按 32 KiB 计费的 32 MiB 信号量，普通下载在申请网络 READ 前取得许可并随响应持有到消费完成；所有活动文件与失效范围转交共用该预算。排队获取许可不启动停收检测，错误/取消自动释放许可；最多每文件 8 MiB 写盘队列、摘要缓存及协议缓冲另计。普通多连接窗口仍在 8–64 请求间起步/扩展，慢连接可缩至四个，但每累计当前窗口数量的完成响应才用平均等待时间评价一次，避免同一批慢响应连续触发减半。单连接、预览与有序归档的窗口规则保持原样。日志增加 read_window 与 connection_stalled；TUN 外层协议、路由、MTU 和复用不由应用修改，也不能从本机 TCP 延迟推断完整代理路径延迟。

阅读入口：[README](../README.md) 提供开发启动，[使用指南](USAGE.md) 说明操作与资源限制，[功能矩阵](SUPPORT_MATRIX.md) 维护当前能力，[验收记录](READINESS.md) 维护验证边界。下文保留分模块实现约束及部分增量设计记录；上传流水线等逐步调整的参数应结合后续条目与当前源码阅读，不能将历史测量当作性能承诺。

`text_encoding.rs` 使用 chardetng 识别无 BOM 传统编码，encoding_rs 严格解码及编码；UTF-16 保持大小端和 BOM 状态。全文打开及保存共用该模块，保存拒绝无法表示或无法往返的字符。`text_chunks::Chunk.encoding` 只在首块提供识别结果（本地及远程一致）；`PreviewTextDecoder` 按标签保留流式状态，避免跨块字符丢失。`LargeTextPreview` 手动切换编码会关闭旧 reader、生成新请求并从头读取，过期响应不得污染新正文；手动选项只影响只读预览，不改变编辑保存参数。自动识别基于已读样本，不能保证所有传统编码准确。

`CsvPreview.tsx` / `csvData.ts` / `csvPreview.css` 为本地、远程及归档文本入口提供 CSV/TSV 只读表格。解析引号内换行、双引号转义及 BOM，以逻辑记录分页，每页最多 100 条，不写回或执行单元格值。`RemoteDocumentDialog` 默认表格并保留原始文本切换；`LargeTextPreview` 传递 `textComplete`，未读取全部内容时暂缓末条记录，表格滚动及“加载更多”继续原有受来源版本保护的分段请求。解析最多 8388608 个 UTF-16 代码单元、10001 条逻辑记录（含可选表头）、256 列，预算或格式错误明确提示；搜索仅覆盖已解析记录。

扫描 PDF 的 JPEG 2000/JBIG2 使用随包发布的 WASM 解码器；`PdfPreview` 开启 `useWasm`，CSP 仅允许本地脚本及 WASM 编译（`wasm-unsafe-eval`），不开放 JavaScript 字符串求值或外部脚本。原先关闭 WASM 会调用大型 JavaScript 回退解码模块，不能用读取完成或 render Promise 成功代表页面已正确显示。

PDF 界面采用 `MediaPreview → read_remote_preview → PdfPreview(bytes)` 的完整读取链路；读取完成前显示字节进度，关闭面板取消读取。PDF.js 只接受完整数据副本，页面浏览与全文搜索不再调用远端。

预览入口先核对请求取消标志，再通过 `preview_owner` 只取得原认证会话的缓存归属，不调用浏览会话的恢复建连。`transfer::read_preview` 租用独占数据连接，避免旧共享会话中未收齐 DATA 的请求阻塞新预览。成功收齐并关闭文件句柄后归还下载池，取消或失败销毁连接。租约共享原认证连接的内存缓存及断开标志，来源属性仍在当前租约核验。`Remote::read_preview_prepared` 复用首个 LSTAT 快照供 OPEN/FSTAT 校验，并预分配完整缓冲；读取范围不得超出已验证大小。每个 Remote 仅缓存最近一份带修改时间、最多 16 MiB 的完整 PDF；路径、大小和修改时间一致才复用，命中也核对读取前后属性并响应取消，断开清空，不跨认证连接或落盘。缓存额外占用最多 16 MiB，读取及二进制 IPC 缓冲仍单独存在；至少 4 MiB 的冷文件通过 transfer::preview_connections 按现有并发设置准备至多三条额外连接，复用已有下载连接池及认证快照，每个辅助连接先验证已存指纹再认证，建连最多十秒，失败退回可用连接。缓存命中及小文件跳过准备。辅助连接只参与本次完整读取，每个句柄分别核对源属性，正文收齐后并行派发各句柄的 FSTAT 并收齐全部响应，避免收尾串行等待多个 RTT；成功读取并完成源核对/CLOSE 后按建连时的信任快照和主会话归属回池；失败或取消并行关闭，不复用残留请求。连接池并行补齐所需会话；额外 OPEN 结果收齐并登记全部句柄后并行 FSTAT，失败仍覆盖全部已知句柄清理；`download_pipeline` 按完成响应从共享范围队列领取未派发分块，多连接初始每条最多八个请求；500ms 内完成逐步扩大至上限，等待超过两秒则收缩后续窗口，但不低于初始的八个请求（调用方上限不足八个时沿用该上限），避免排队延迟把预读压至两块，已发送请求不重放或迁移。单连接保持原窗口。最多四连接各 64×128 KiB 在途正文合计 32 MiB，完整文件缓冲另受 32 MiB 限制。不能把缓存命中耗时当成首次网络读取吞吐。

`usePdfViewport.ts` 根据自然尺寸与估计尺寸生成页面偏移，二分定位当前页，只挂载视口及上下 600px 范围内正文；用页内比例锚点恢复尺寸变更前的位置，禁用浏览器自动滚动锚定避免重复补偿。缩略图固定 246px 行高，只挂载视口附近行。`pdfTextCache.ts` 按最近使用淘汰最多 32 页、约 4 MiB 字符/偏移数据，换行空白与软连字符规范化后映射回 TextLayer 原始字符串偏移；查询变化丢弃过期结果，结果最多每 100ms 发布一次。画布与文字层错误分开处理，文字层失败保留画布。`MediaPreview.tsx` 在网络读取时并行导入阅读器，缩略图绘制等待首个正文画布，目录按页签需求解析；开发计时只输出数字，不输出路径/文本/连接信息。远程图片读取使用 `Remote::read_preview` 的每连接 64 请求乱序窗口及协商的下载分片（上限 128 KiB），按显式偏移拼回最多 32 MiB 内容，复用原读取生命周期与二进制 IPC；慢首屏需结合首批进度、完整读取、解析和首画布耗时继续分析。

PDF 阅读器：`PdfPreview.tsx` 协调页面导航、视口、缩放和旋转；`PdfSidebar.tsx` 按可见范围渲染缩略图，隐藏时保留实例、宽度和滚动状态，并停用缩略图绘制。`PdfOutlineView.tsx` / `pdfOutline.ts` 以稳定序号展开目录模型，每批最多八个目标解析请求，只跳转文档内部页目标；无效或外部目标不参与章节高亮。标题搜索显示命中及祖先，不改动原折叠集合；26px 行高的目录仅渲染视口及上下五行，横向宽度按标题测量，视觉缩进最多 20 层。当前页高亮独立于滚动，用户主动点击定位按钮才滚动，避免隐藏/重开或窗口变化覆盖用户位置。目录异步读取和解析在卸载后丢弃结果。

`usePdfReadingMemory.ts` / `pdfReadingState.ts` 在本机 WebView localStorage 的 `termrill.pdfReading.v1` 保存最多 50 份文档的 PDF 指纹、页码和缩放模式/比例；不存路径、文件名、正文或凭据，不改变连接配置及密码保存策略。恢复后等待布局落定才写入，400ms 合并更新，关闭/切换文档及 pagehide 时提交最后有效快照，卸载时移除页面事件监听；不恢复页内偏移和旋转。记录结构异常不覆盖原值，读取/写入失败提示后仍可阅读；关闭期间的写入失败不阻断资源释放。

`usePdfSearch.ts` 防抖后逐页提取文本、保留最多 10000 个命中位置，查询或文档变化后丢弃过期结果；`pdfSearchMatches.ts` 保留原始字符偏移。`PdfPage.tsx` 在原有有界画布上叠加 PDF.js TextLayer，支持选择及命中高亮，关闭/离开预加载区时取消渲染并释放画布和文字节点。文字与目录内容作为文本展示，不注入 HTML 或执行文档脚本。

`archive_sources.rs` 使用 FuturesUnordered 持续调度最多 16 个来源扫描，完成即处理子项并补充任务；项目总量检查包含队列、在途任务和已收集结果。任何错误或取消均停止派发并排空在途扫描，保留目录 CLOSE。最终按名称排序，网络完成顺序不改变 ZIP 条目排序或重名校验。

`archive_read_pipeline.rs` 仅用于带扫描属性快照的完整归档来源读取，以 FuturesUnordered 收齐响应、BTreeMap 按偏移交付压缩器。远程 pack/add 通过 `archive_session.rs` 从原认证连接的数据池借用独立连接组，按现有并发设置最多四条；成功收齐并关闭句柄后回池，失败或取消关闭整组，不占用浏览会话。小文件在连接间轮转，至少 4 MiB 的来源跨连接交错读取，每个句柄分别核对来源版本。请求窗口按实际连接数放大，接收及乱序缓存合计不超过两倍总窗口；最多八文件、每连接八请求、四连接、128 KiB 分片时范围正文上限为 64 MiB，另有原 8 MiB channel 队列及消费者当前块、协议缓冲。单文件每连接 32 请求时最大范围正文为 32 MiB。首块持续阻塞时预算填满即停止新增读取，不随文件大小增长。普通下载和 ZIP 随机预览调度参数不变；源校验、取消与 CLOSE 仍由原读取生命周期负责。

修改前先阅读 [AI 开发规范](../AGENTS.md) 和 [使用说明](../README.md)。本文件说明现有实现与容易误改的约束。

### 2026-10-21：近期规划实现

- `TransferRecoveryIntent` 只保存所选任务 ID 和配置/端点身份，不保存凭据或 ConnectRequest。正常认证成功后按相同身份最多消费一次，取消或端点变化清除意图；后续仍调用原 retry_transfer，由后端验证原任务端点和活动状态。存在未结束任务时禁止通过恢复入口重连，重试与移除使用工作区内互斥状态。
- `directoryHistory.ts` 记录成功导航，失败请求不提前移动历史索引，新分支截断前进记录，每面板最多 50 步。`directoryLocations.ts` 将收藏和最近目录存于 `termrill.directory-locations.v1`，按配置 ID、目标和跳板身份隔离；单范围收藏/最近上限分别为 50/20，最多 100 个非空范围。每次保存重读存储，清空收藏与最近后释放范围。多窗口同时写入不是数据库事务。无密码、令牌及私钥内容。
- `DirectoryLocationMenu` 通过 portal 避免面板裁剪，外部点击、Esc、导航和外部滚动关闭；导航仍走原 list_local_page/list_remote_page。存储写入失败不冒充保存成功。
- `useWorkspaceLayout` 只将尺寸保存到 `termrill.workspace-layout.v1`，拖动期间只更新内存，结束才落盘，同窗口与 storage 事件同步其他工作区。读取时限制面板比例及终端尺寸，视口另限制终端显示高度。分隔条持有指针捕获，取消时还原，已有 ResizeObserver 负责终端适配。
- `CommandPalette` 只调用已有界面动作，不运行 Shell。仅可见工作区监听快捷键，输入框、编辑器、终端和其他弹窗内不接管快捷键；命令面板提供焦点约束、禁用状态及关闭后的焦点恢复。
- `BatchRenameDialog` 绑定打开时的连接 ID、目录和选择快照，最多 100 个普通文件。先分页枚举完整目录（最多 10000 项）核对来源属性与目标冲突，再依次调用原 rename_entry；改名不自动重放，失败或取消停止后续派发，已确认结果不回滚。远程连接变化后禁止下一项。目录快照与实际改名仍存在竞态，不提供批次事务；原本地改名接口的存在性检查也不是原子 compare-and-swap。

## 统一异步 SSH/SFTP

生产连接、认证、目录、属性、权限、删除、文本及媒体预览、归档、下载、上传和终端统一使用 russh/russh-sftp。ssh2 仅为 dev-dependency，旧协议实现只在 cfg(test) 下编译，用于既有故障回归；生产没有同步 SSH 回退。

原生 SFTP 连接启用 russh 的 flate2 能力，优先协商认证后启用的 `zlib@openssh.com`，保留 `none` 兼容服务器；不协商认证前的传统 zlib。协商在新建会话时生效，不能给正在运行的连接直接切换算法。密钥交换回调只记录接收/发送压缩算法，不记录共享密钥或认证信息。此优化针对线上字节量，已经压缩的内容收益有限并增加计算开销，不代表修复了所有传输停顿。

`transfer_schedule.rs` 位于传输父模块，上传和下载共同使用 SmallWindow 与大小交错队列。下载将不满 4 MiB、不跨连接分片的来源全部放入自适应队列，并限制这些文件同时活动的源字节合计不超过 32 MiB（没有活动文件时总放行）；至少 4 MiB 的大文件独立遵守配置的 1–4 个槽位。上传仍以 256 KiB 划分。总活动文件数受 max_files 限制，协议句柄仍由 Remote permits 管理。失败停止新派发并排空活动协程；暂停不启动新文件，也不将未派发队列误判为完成。下载速度为独占租约所有连接最近一秒收到的 DATA 正文字节率，包含未收齐分片的正文，不计协议头和状态响应；处理字节进度单独推进，暂停归零，剩余时间仅在有有效速度且未收齐数据时估算。

`transfer_download_session.rs` 为整个下载任务独占租用现有传输池；下载不再占用浏览缓存的 SFTP/TCP 会话。池命中必须匹配主连接 closed 标记身份及当前 known_hosts 快照；未命中通过与上传相同的验证/认证入口建连。Remote::owned 不启动后台维护，也不留存跨操作预览句柄，下载协调器先扫描一次，存在至少 4 MiB 普通文件时按并发设置并行补齐总计 1～4 条独立连接。64 个范围请求交错分配到这些连接，各句柄 OPEN 后及读完均核对源大小/修改时间；分片大小取参与连接限制的最小值。小文件只使用主连接。仅成功且未取消/断开时归还全部 native，错误则关闭全部租约，不能复用未知响应状态。后台维护仍提供空闲预热连接，主连接断开后池统一释放。独立 TCP 会话隔离排队，实际下行吞吐另受网络和服务器制约。

`ssh.rs` 建立已验证的原生会话；`remote_async.rs` 缓存该会话，注册表锁只用于取得句柄，不跨网络等待。目标与跳板分别验证 SHA256 指纹且先于认证。主连接关闭标志传播至任务、预览与终端，后台维护协程释放会话。保活由协议库驱动，不使用线程轮询 socket。

`remote_listing.rs` 处理分页；`remote_chunks.rs` 按请求标识复用顺序读取句柄，旧关闭请求不影响新读取；`remote_write.rs` 写独占临时文件，收齐 WRITE、确认 CLOSE、核对当前目标与编辑摘要后安装。读取流水窗口为八个最多 32 KiB 范围请求；总句柄数受服务端 limits 和信号量限制。

`remote_delete.rs` 的 delete_async_pipeline 使用最多 16 个扫描请求，扫描期间最多 32 个删除任务；扫描全部结束后删除窗口扩至 40，合计最多 40 个在途任务。READDIR 每返回一批即派发 UNLINK，目录进入前重新 LSTAT；目录 CLOSE 与全部子项删除确认后立即派发自身 RMDIR，不等待无关分支。新目录只在句柄预算可立即取得时派发，CLOSE 优先释放句柄，OPEN/READ 交替推进；预算不足时继续 READ，避免单句柄预算下死锁。已满足依赖的 RMDIR 插入队首，优先推进目录收尾。日志补充各类请求首次开始与最后完成时间，区分主体与尾段等待。scan_complete 记录扫描完成时待删除及在途数量；unlink_queue/rmdir_queue 记录本地排队时间，与协议响应等待分开统计。队列计时从项目具备删除条件开始，不包括等待子项完成的依赖时间。失败停止派发并收齐在途请求，再释放仍打开的目录句柄，不自动重放删除。根路径拒绝删除，链接只删除自身。流式遍历不是远端目录快照，服务器枚举或其他程序并发修改导致剩余项时，RMDIR 失败并报告未完成，不把请求已发出当作成功。批量属性扫描与修改分别最多 16 个任务，先完整扫描再后序修改，保留乐观属性检查。

下载目录扫描最多 16 个异步任务，复用 READDIR 属性；排序后分配稳定续传编号。文件下载使用 64 个范围读取请求，buffer_unordered 按完成顺序交付偏移和正文，容量 64 块的队列连接独立 Tokio 写盘协程。download_read_size 独立于归档范围大小：服务端明确声明 max_read_len 时取 128 KiB 与读取/包长上限的较小值，未声明时保留标准分片；不得将服务端较小上限向上 clamp。SSH 接收窗口为 8 MiB，单包上限 65535；SFTP 帧可跨 SSH 包。已完成范围及时补充请求，写盘按偏移定位。写入累计 512 KiB 或定位新偏移前确认待写批次，成功后才将待确认范围合并为连续边界。失败截断至连续完成边界与原续传前缀的较大值，下次仍核对前缀。SHA256 按连续偏移递进，乱序正文缓存限 8 MiB；超预算范围只落盘，最终只补读未形成摘要的尾部，通常无需全文件重读。源大小/时间核对、最终同步和摘要完成后才安全安装。需要顺序正文的其他读取入口保持 buffered。目录比较最多 16 个枚举任务、八个摘要任务。失败不自动重放写入。

`archive_zip_index.rs` 首次读取最多 30000 字节尾块，在一个 SFTP READ 内一起获取 EOCD 与常见小中央目录；注释超出尾块时再有界搜索最多 65557 字节；读取 ZIP64 与中央目录，以仅含元数据的内存 ZIP 复用原库的名称编码、加密、大小和类型解析；该内存表示仅供列表，不用于内容校验或解压。`archive_zip_remote.rs` 为真实条目提供 Read/Seek 适配器，范围 READ 由 Tokio 驱动，最多 32 个并发、缓存最多 2 MiB；归档单个 READ 最多 30000 字节，保留预览随机读取的小范围策略，不与完整下载共用大分片设置，同时遵守服务端数据/包长度限制；多块仍流水并发，其他普通读取与上传块大小保持原值；`archive_zip_pool.rs` 按连接/面板/路径独占租约，复用句柄、原始索引和 2 MiB 数据缓存；OPEN 后核对实际句柄属性，范围请求不重复发送读取前 FSTAT；完整解码后统一核对源属性，确认与索引快照一致才返回内容，解码到 EOF 保留 CRC/AES 校验；缓存命中展示面板快照，不逐图片发送 FSTAT。局部头和负载合并预取：已缓存局部头使用精确长度，首次以压缩长度加 4 KiB 头预算读取，不再强制预取 256 KiB 相邻内容；更长的合法头按需补齐。READ 响应日志记录请求字节、实际字节、单次耗时和批次累计耗时，区分真实网络响应与消费等待。索引 Seek 命中内存原始记录。刷新/关闭递增全局租约代号，迟到请求不得重新入池；同面板在途读取不重叠，其他面板可独立并发。缓存最多八个空闲句柄、64 MiB 计费数据，需留出至少一个可用句柄预算；五秒维护检查断开和 120 秒空闲过期，CLOSE 在后台确认后释放预算。取消、失败和未入池句柄均后台关闭。首次路径与源属性请求最多 16 个并发，祖先全部验证为普通目录后才 OPEN。目录标识为中央目录与源大小的 SHA256，明确区别于整包摘要；全包操作对照目录标识后计算完整摘要，修改安装前仍重新核对全包摘要。同大小、同时间且未更新中央目录的改写不由目录标识检测，预览完整读取仍通过 ZIP CRC/AES 验证。

ZIP/压缩流库提供同步 Read/Seek 接口，因此解码、重建和本地磁盘工作保留专用工作线程；ArchiveIo 在该线程衔接原生异步范围读写，网络请求仍由 Tokio 驱动，没有调用 ssh2。归档文件顺序安装以保持冲突预检与已安装结果的语义，不为并发而跳过完整性检查。

远程打包及向 ZIP 添加来源由 `archive_sources.rs` 扫描：选中路径的共同父目录只在本次扫描检查一次，最多 16 个异步任务；子目录复用 READDIR 类型和大小，属性不完整才回退 LSTAT。扫描快照传给源文件读取，避免逐文件重查祖先和读取前的重复 LSTAT；OPEN 后仍用 FSTAT 对照扫描大小与修改时间，读取结束再核对句柄属性，失败不会安装生成的 ZIP。快照不跨操作缓存；SFTP 无法消除扫描与打开之间父目录被替换的竞态，来源目录不应同时被其他程序替换。普通预览、解压及目标安装的检查流程不受此扫描优化影响。性能日志记录扫描耗时、项目数、父目录检查数及来源 LSTAT 数，便于确认是否出现属性回退。

创建 ZIP 的字符串进度通道兼容普通阶段文本，同时发送 `kind=packProgress` 的 JSON 事件：扫描发现数、处理文件数、源字节总量/已读量、ZIP 缓冲区实际长度及已确认上传量。事件最多每 100 ms 更新，阶段切换和完成立即发送；扫描计数增量维护，避免每次进度遍历全部清单。`ArchivePackProgress.tsx` 在主体顶部展示 ZIP 四阶段，非 ZIP 另含编码阶段、真实计数和客户端已用时间，不按未知压缩率猜测全流程百分比。源处理与 ZIP 上传分别使用自身字节总量；读取速度为读取阶段平均速度。上传只统计成功 WRITE 响应，CLOSE 后进入目标确认和安装阶段，安装成功才发送完成；失败/取消保留报告，过期通道消息按操作代号丢弃。生成 ZIP 仍在客户端完成，来源通过有界流水读取后顺序写入 ZIP，随后上传；没有执行远端压缩或边压缩边上传。

`archive_pack_read.rs` 将远程打包/添加来源的异步读取与 ZIP 计算隔离：一个作用域协调线程驱动最多八个文件协程，多个文件时每文件八个范围请求；单文件仍保留 32 请求窗口。完整来源按服务端限制使用最高 128 KiB 分片；每文件 channel 容量按块长和最多八个活跃来源分摊 8 MiB 总预算，容量上限 64 块，成功读完也须等待消费者确认才释放预读任务槽，避免小文件提前完成后逐步缓存整个目录。压缩在归档工作线程执行，预读不因同步 ZIP 写入停止调度；来源属性、读取后校验和 CLOSE 成功后才报告文件处理完成。消费失败或取消先标记停止并释放全部接收端，再收齐协程关闭句柄；借用的取消标记、来源清单与连接不逃出操作生命周期。性能日志将等待数据的阻塞时间、ZIP 写入计算时间和最后 ZIP 收尾时间分开，等待时间不是整个网络下载的耗时，不能将重叠阶段相加解释为远端耗时。

`archivePrefetch.ts` 管理面板小图预取与 32 MiB Base64 LRU。每次版本/密码变化递增代号，丢弃迟到结果；关闭与用户取消同时取消预取。每次只进行一个后台解码任务，其范围 READ 仍并发。前台点击同名条目复用 Promise；不同条目取消当前后台请求，等待它退出租约后派发前台，不等待剩余队列。目录展开、当前列表和悬停提供候选；单图最大 512 KiB，最多六项与 2 MiB 压缩数据，连续浏览逐渐扩大邻居数量，随机浏览仅预取两张。加密条目不隐式读取，前台仍通过原有密码/CRC/AES 流程。

`archive_zip_shared.rs` 共享不可变索引与已校验原始范围，各 Reader 保持独立游标。共享键限定同一 Remote 实例、路径、大小/修改时间与索引版本；新打开先通过路径与实际句柄检查，刷新列表始终重新读取中央目录。最多 16 个归档，索引和热范围合计 64 MiB；超额范围可从应用缓存目录 `zip-ranges` 恢复，读取前核对长度及 SHA256。落盘使用容量四的后台队列，不持共享锁等待磁盘，缓存目录最多 128 MiB，只清理自己的 `.block` 文件；磁盘失败退化为未命中。磁盘内容没有可信跨会话索引，断开/重启不直接恢复旧记录。成功完整解码并核对源属性后才发布共享缓存；取消只恢复进入操作前已验证的索引/范围，不发布部分下载。面板租约失效后不能重新缓存句柄。

PTY 使用独立异步通道和有界输入 channel；握手前到达的欢迎内容保留，关闭终端只关闭该通道。远端并发改名仍存在协议无法消除的检查与操作竞态。

## 模块地图

`useArchiveController` 将首次列表读取延迟至下一事件循环，在 StrictMode 的同步 setup/cleanup/setup 中清除尚未启动的定时器；避免第一轮被取消、第二轮被 active 拦截而不加载内容。每次 effect 挂载使用独立 snapshot，cleanup 只释放该轮 snapshot，迟到关闭不会使新轮租约失效；定时器启动前显示读取状态。

`LargeTextPreview` 将首次 IPC 延迟至下一事件循环，在 React StrictMode 的同步 setup/cleanup/setup 中取消未发出的首次读取，避免开发模式重复下载、占锁和重开句柄。真实卸载取消未发出的定时器，已经发出的请求仍按请求标识关闭句柄；不关闭 StrictMode。分段日志记录首次/后续、句柄复用、连接锁等待与总耗时，便于区分生命周期重复和服务器延迟。

`FileActions` 对超过 64 KiB 的远程文本优先使用 `LargeTextPreview`；`remote_async::Reader` 首批最多 8 KiB，后续最多 32 KiB，收到一次 DATA 即返回，逐请求非阻塞等待；每个连接最多一个预览句柄，打开时通过 FSTAT 核对 READDIR 属性，此后每累计读取 256 KiB 再通过 FSTAT 检查大小/修改时间。前端使用独立请求标识，关闭/EOF/错误时发送 close_text_reader，旧关闭请求不能关闭新预览。句柄随连接释放，后续分段复用 OPEN 和预读状态，CLOSE 不阻挡成功首批返回。分段返回前检查普通文件类型和版本戳，UTF 解码器跨块保持状态。小于等于 2 MiB 的文本保留显式全文编辑入口，进入后仍走原保存校验；分段正文不得作为可保存文档。此优化减少重复属性请求，但不影响远端 OPEN 响应耗时。

原生异步上传基础实现由 `transfer_async.rs`、`transfer_async_ssh.rs`、`transfer_async_precheck.rs` 负责；当前加速路径另使用 `transfer_upload_*` 独立模块与连接池，具体调度见下文上传实现记录。russh 与 russh-sftp 提供原生异步连接和多请求 SFTP 会话；上传按任务文件数与大小选择基础或加速原生路径，不包装同步 ssh2 调用。目标与跳板分别校验原 SHA256 信任指纹，主连接与上传共用原生算法协商，验证实际指纹后再认证；未知或变化的指纹登记确认请求，认证前拒绝。密码、私钥、交互认证及系统 Agent 的接口保留；Windows Agent 支持 OpenSSH 命名管道与 Pageant。标准跳板使用原生 direct-tcpip 通道并由上传连接持有。

上传本地枚举在任务工作线程执行；只读远程预检对不超过四项的任务直接 LSTAT，较大任务按父目录批量 READDIR、最多 16 个并发查询，权限不足时并发 LSTAT 回退。通过后按路径深度分层创建目录，同层最多 16 个 MKDIR 异步请求，父层完成才进入子层，再混合调度大小文件的有界协程。每连接初始 64 个在途 WRITE、按确认吞吐探测至最多 256 个，大文件单块在服务器明确允许时最多 128 KiB；至少 4 MiB 文件跨连接写入，大文件默认三个文件并发，最大四个，小文件初始八个、最多三十二个；服务器 limits 扩展可进一步降低块长和句柄数。大文件同样使用流水写入，确认顺序不影响显式偏移。原扫描下标和任务清单路径格式保持稳定，兼容此前续传记录。

扫描状态计时由 useTermRillWorkspace 在首次 scanning 事件记录 performance.now，后续同状态事件保留开始时刻；离开 scanning 后停止展示，再次进入时重新计时。TransferQueue 仅在存在 scanning 任务时启动每秒刷新定时器，卸载和扫描结束时清理，队列折叠或切换标签不重置工作区计时。恢复任务缺少开始时刻时标记为观察时间，避免伪造后端实际耗时。scanStartedAt、scanTimerEstimated 仅为前端字段，不写入任务配置或改变传输协议。

删除诊断：delete_entry 记录工作线程调度、连接锁等待和 SFTP 准备耗时；普通删除报告等待连接、准备文件协议、检查删除路径、正在删除阶段，避免把实际删除误标为准备。DeleteTrace 对父目录/目标 LSTAT、READDIR、UNLINK、RMDIR 记录 begin/end、进程内递增诊断编号、深度、耗时及成功状态，不记录路径和正文。递归动态队列及空目录删除同样记录逐请求耗时；诊断保持原阻塞调用、类型检查、并发数量和失败语义，不自动重放删除。pipeline=true 表示遍历任务流水调度，并不表示单个 SFTP 连接存在多个在途 UNLINK；兼容回退路径的每工作线程仍等待单次调用返回才领取下一项；request_pipeline=true 才表示标准 SFTP v3 的多请求在途窗口。

## IPC 与事件

前端使用 `invoke` 调用 Rust 命令。Rust Serde 和 TypeScript 的字段均使用 camelCase；调整字段时必须同时维护两端。命令错误包含 `message`，需要确认指纹时还包含 `hostKey`。

- 配置：`load_profiles`、`save_profiles`、`load_preferences`、`save_preferences`。
- 信任与连接：`known_hosts`、`trust_host`、`forget_host`、`connect`、`disconnect`。
- 文件：`list_local`、`list_remote`、`pick_path`、`create_directory`、`rename_entry`、`delete_entry`、`open_remote_text`、`save_remote_text`。
- 传输：`start_transfer`、`cancel_transfer`、`pause_transfer`、`retry_transfer`、`pending_transfers`、`discard_transfer`，通过 `transfer-progress` 推送结果。
- 终端：`start_terminal`、`terminal_input`、`resize_terminal`、`close_terminal`，通过 `terminal-output` 推送字节与关闭结果。

传输的 `bytes`、`total` 使用字节，`speed` 使用平均字节/秒。终端数据是字节数组，交给 xterm 解码；不要逐事件转换成字符串，UTF-8 字符可能跨事件分片。

`transfer::run` 拦截执行器发出的终态，先清理任务注册表、更新持久化清单，再发送最终 `transfer-progress`。前端收到失败时可立即重试或移除记录。重试取得运行名额后先保存更新过的连接 ID；保存失败则撤销名额和暂停标记、恢复原任务，不创建工作线程。

新增认证命令 `answer_auth`，事件 `auth-challenge` / `auth-challenge-closed`。每个提示使用临时 ID 和有界回答通道，超时或关闭后移除，不能复用过期提示。凭据命令为 `credential_support`、`save_credentials`、`load_credentials`、`delete_credentials`；连接配置不包含密码。

## 状态、所有权与清理

上传预检和数据传输共用一个原生异步连接，移除提前建立同步扫描连接和多个上传工作连接的逻辑。SFTP 请求等待不占用 Tokio 执行线程；本地文件使用 tokio::fs，私钥读取与解密单独使用 spawn_blocking，不把它作为网络异步实现。

原生上传的 WRITE、OPEN、CLOSE、SETSTAT 和 RENAME 由 russh-sftp 的请求编号队列分发。单文件的所有 WRITE 成功后确认 CLOSE，核对源变化并通过协调器提交屏障，才允许安装和摘要持久化。各文件安装仍可与其他文件的网络请求重叠。未知结果直接失败，不重放可能已经成功的写入或替换。

上传进度使用容量 64 的 Tokio channel，协调器独占字节数和摘要保存；成功安装才交给原任务清单入口。一般失败停止新文件、排空已有协程，保留可续传临时文件；取消只删除本次实际打开且验证过的临时文件。进入备份/恢复提交后不因取消打断恢复，避免旧目标被移走后无法恢复。下载保留原有每线程最多 16 条摘要、协调器批量保存的确认队列。

旧上传安装队列 `transfer_atomic.rs` 和同步预检缓存 `transfer_targets.rs` 已移除。原生上传直接使用服务端声明的 posix-rename@openssh.com 扩展；仅明确“不支持”才转为 SFTP v3 备份/恢复。预检不存在的目标使用普通 RENAME，避免覆盖并发出现的同名文件。编辑与归档写入也通过 remote_write 调用同一原生安装策略。预检不是目录锁，远端并发换名仍存在竞态。

断开先设置停止标记，再移除连接注册项。已启动任务可能仍持有 Arc，因此删除注册项不代表任务瞬间消失；复制循环在下一次检查时退出。窗口销毁时同样通知任务和终端停止。

前端目录请求使用递增序号拒绝过期响应，远程响应还要匹配连接 ID。长期事件回调通过 ref 读取当前目录和连接。订阅先于任务启动；异步订阅或终端启动在组件卸载后才完成时，也必须释放资源，兼容 React StrictMode 的重复挂载。

## 认证与持久化边界

顺序是握手 → 验证主机指纹 → 认证。跳板和目标主机分别执行此顺序。未知或变化的指纹先返回挑战，用户确认后重试连接；确认内容必须与后端待确认挑战匹配。

`Profile` 保存地址、用户名、认证方式、私钥路径及跳板配置；`Secrets` 独立存在于连接请求与会话内存中。`Config` 不包含 Secrets。不能把整个 ConnectRequest 序列化成配置，也不能记录认证请求。配置文件位置和支持的密钥格式见 README。

## 路径与文件完整性

本地路径遵循操作系统规则，远程路径遵循 POSIX 规则。下载必须校验远程名称，拒绝路径逃逸、Windows 保留名称和数据流形式。符号链接通过 readlink/symlink 保留目标，不当普通目录递归跟随；未勾选覆盖时保留同名保护；勾选后只允许链接替换链接。links.rs 独立处理临时链接、旧链接备份及失败恢复，不向链接调用 chmod；旧备份清理失败或恢复失败时报告位置。标准文件系统和 SFTP 操作仍有并发替换竞态。任务摘要以 `link:` 前缀区分链接目标和普通文件内容，续传核对两端链接目标。Windows 目录联接和特殊文件不支持传输。Windows 下载链接需要先判断远端目标类型，不能判断时明确拒绝。

传输先扫描并检查同名冲突，再写目标目录中的临时文件。扫描不是锁定远程目录，安装时仍需检查目标。非覆盖安装应保留同名保护；覆盖 SFTP v3 文件时先备份旧文件、安装新文件，失败则尝试恢复。恢复失败必须报告备份位置，不能隐藏数据完整性问题。

显式取消清理当前临时文件；失败、断开和退出保留临时内容供续传。目录传输不是事务：已完成的文件和已创建的目录不回滚。任务清单单独持久化到 transfers.json，不包含 Secrets；已完成文件保存 SHA256，重试时核对两端后跳过，未完成文件逐字节核对临时前缀后追加。原生上传前缀校验与后续写入共用一个句柄，通过明确偏移避免读取预取状态影响写入。安装前检查本次复制字节数、源大小和修改时间，拒绝已检测到的源变化；这些检查不能保证识别同大小、同修改时间的并发改写。更新清单失败通过 transfer-persistence-error 提示界面。不要把取消描述为撤销整个任务。

## 验证与能力范围

`transfer_cleanup.rs` 负责移除任务时的临时文件清理。下载在本地执行，上传核对连接与原服务器配置后执行 SFTP；单文件直接定位下标 0 的临时路径，目录枚举目标树，仅删除名称严格匹配任务 ID 与数字下标的普通 `.part` 文件。不依赖源路径仍存在，不跟随链接和目录联接，最多深度 128、扫描 100000 项。正式文件、目录和回滚备份保留。清理在阻塞线程中执行，并占用任务注册项防止同时重试；清理失败保留任务，记录保存失败恢复内存记录，允许再次移除。

递归下载扫描复用 READDIR 返回的子项属性；打开源文件后仍检查属性与复制后的变化。`transfer_download_file` 使用两个借用协程并行接收与写盘，64 个按完成顺序交付的范围请求、容量 64 块的队列和 512 KiB 批量写入确认；队列有效载荷最多 8 MiB、在途范围正文最多 8 MiB，另有 8 MiB 摘要乱序缓存及协议缓冲，不会按文件大小增长。写盘失败丢弃接收端以唤醒读取端，两个协程 join 后才返回，读取端保留 CLOSE；全部前缀核对、源变化校验、flush 和 sync_all 成功后才安装目标。暂停/限速作用于写盘消费端，网络只允许填满有界预读。日志分别记录接收写盘总时长及本地 IO/摘要时长，阶段重叠不能相加。原生上传以最多 32 KiB 写块发送，按服务器限制下调；请求预算与正文上界见下文上传流水线说明，另有库的协议缓冲。已有临时文件逐字节核对前缀，不能将块数或缓冲大小当作实际加速倍数。

格式检查、构建、Clippy 和测试命令见 AGENTS.md。协议、覆盖、取消和路径行为变更使用本机临时服务验证；该服务通过不等于公司的真实堡垒机已验证。

当前支持标准 SSH direct-tcpip 跳板；通用多轮交互认证已接入；厂商网页审批和专用协议未适配。Windows 密钥限制、SSH Agent 验证状态、暂停恢复及安装包状态分别维护在使用指南、功能矩阵和验收记录中，功能变化时同步更新。

## 可配置传输与目录同步

`TransferSettingsForm.tsx` 保存并发数（1～4，默认 3）和单任务限速（字节/秒，0 为不限速）。`transfer_rate.rs` 的预算由同一任务的工作线程共享，等待期间继续响应暂停和取消；限制的是复制的有效载荷，不是 SSH 协议的精确线速。不同任务分别计费。

`transfer_journal.rs` 在文件完成后追加单项摘要并同步日志；任务快照写入并同步后再合并日志。启动时重放完整记录，截断未完成尾行，避免每个小文件都重写累计清单。快照与日志共用任务锁。

`directory_sync.rs` 比较两端当前目录，递归包括隐藏文件；同大小文件比较 SHA256。报告新增、内容不同、相同、目标独有和类型冲突，跳过链接与特殊文件。深度限制 64 层、每端 100000 项。界面每页 100 项；选中新增或变化项目后仍通过传输确认和覆盖选择。任务持久化所选远程路径，扫描时剪枝。目标独有项目不删除；预览不锁定文件系统，比较后发生变化应重新比较。

## 数据阶段停滞控制

### 连接弹窗布局

`DeleteConfirmationDialog.tsx` 与 `deleteConfirmation.css` 管理删除确认展示，不调用文件操作 IPC。`FileActions.tsx` 继续管理删除顺序、已完成数量、部分失败后的剩余路径及列表刷新。类型来自当前目录列表，未知项目不推断为目录；拆分路径只用于展示，不改变后端收到的路径。

`RemotePermissions.tsx` 使用 `remotePermissions.css` 限定属性弹窗布局，保留打开时绑定的连接/路径、所有者与权限独立 IPC、expectedMode/expectedUid/expectedGid 检查。展示重构不改变特殊权限位保留规则。

`BatchPermissions.tsx` 与 `batchPermissions.css` 管理批量设置展示，沿用原有权限/所有者独立命令、递归参数和逐项结果。预览只转换九位普通权限，不表示读取了每个项目的特殊位；后端继续处理特殊位。路径没有类型信息，使用通用项目图标而不推断文件夹。

### 批量权限任务生命周期

任务使用 taskId 和 Channel<BatchProgress> 注册取消标志，在异步结束后移除。扫描完整结束后按最深目录优先修改；每层最多 16 个原生异步 SFTP 任务。保留 expectedMode/expectedUid/expectedGid 检查、特殊位和写后核验；已确认修改不回滚，取消停止新任务并收齐已派发请求。engine 为 async-sftp，已移除远端 Shell 探测、脚本与同步连接回退。

### 工作空间布局与操作入口

`WorkspaceHeader` 使用 `workspace.css` 中限定于会话工作空间的紧凑布局。`FilePane` 的预览与删除按钮沿用 `FileActions` 提供的回调，删除确认及文档保存逻辑保持原有链路；目录和符号链接不启用文件预览按钮。列表行高与虚拟滚动参数保持一致，移除面板最大高度限制，队列通过内部最大高度避免挤占全部空间。最终态任务不显示暂停或取消入口。

ArchiveEntryTable 按路径段进行自然排序，折叠集合只过滤可见行；文件操作和选择仍传递原始 entry.name。层级处理通过 useMemo 缓存，最多挂载 150 行。

ArchiveEntryTable 缓存包内目录模型、自然排序与真实条目映射；导航只改变展示范围，不发起新的包读取。虚拟目录的选择和下载转换为实际条目名称，复用后端已有目录匹配规则；不安全条目在根目录可见但不可选择或预览。搜索覆盖整个缓存模型，分页每页最多 150 行。

PathBreadcrumbs 将已加载路径转换为导航段，分别处理 POSIX 根、Windows 盘符及 UNC 共享根；点击和编辑均复用 FilePane 的 onNavigate，不增加后台目录查询。

### 统一错误呈现与诊断边界

`errorDiagnosis.ts` 将明确的路由不可达、DNS 解析失败、连接拒绝、超时及 SSH 算法协商文本分类；孤立的系统错误数字不能用于猜测平台或原因。连接场景的权限建议与文件操作分开，SSH `Permission denied (publickey,...)` 先归入认证。分类仍是展示建议，不跳过指纹校验或自动更换认证方式；网络细分类继续保留显式重连后续传入口。

`transferObservation.ts` 仅在收到普通进度事件时记录本页面单调时间；字节数或总量变化重置进度观察，离开 running 阶段清空，恢复页面及重新进入 running 从当前时刻观察。5 秒未收到事件时速度样本视为过期，隐藏主速度及 ETA；连续 10 秒进度字节不变且尚未收尾时提示等待确认，不等同网络停收。`TransferDiagnostics` 展示固定说明及数字快照，用户先展开再复制；不序列化任务，不记录任务 ID、地址、路径、原始错误或凭据，不持久化或上传。它不修改后端 30 秒停收隔离、限速、并发和重连逻辑；现有队列计时器刷新状态并在无活动任务或卸载时清理。

`errorDiagnosis.ts` 对现有错误文本进行保守规则匹配，返回分类与建议，不改变 IPC、任务权限、认证、覆盖及取消逻辑。分类顺序优先指纹与认证，再识别空间、权限、冲突、网络、缺失、格式与取消；未知情况保留原错误。

`ErrorNotice` 统一连接、传输、归档、文本编辑和媒体加载错误展示。调用方显式提供可选恢复回调；不会推测或自动执行恢复。诊断由用户先展开再复制，内容采用固定场景、阶段及分类字段，主动排除原始异常和上下文数据，不依赖正则脱敏来保证秘密安全。仅复制到本机剪贴板，不存储或上传。剪贴板失败保留摘要供手动复制。后续结构化后端错误码应逐步替代文本匹配，不能将当前展示层称为全量诊断系统。

远程文本读取与图片/PDF 预览复用 Connection::directory_sftp 缓存的 SFTP 子系统，避免每次预览建立新通道；读取期间保持连接互斥保护。预览超时附带刷新目录及重连建议，保留原始错误，不自动重试、自动重连或延长会话全局超时。共享子系统不保证已经失效的 SSH 会话能够恢复。

archive_decode.rs 处理 TAR 与 GZIP/Bzip2/XZ 解码；archive_extra.rs 接入 sevenz-rust2 的 7Z 顺序解码，archive_rar.rs 使用 UnRAR TEST 回调读取 RAR，不调用原生 EXTRACT。RAR 独占临时源文件由 RAII 清理，回调禁止分卷加载并在每块检查取消、声明大小和内存写入上限；链接与特殊属性拒绝。RAR/7Z 快照按面板和内存中的密码摘要隔离，刷新或关闭清除该面板全部快照；密码不写磁盘或日志。RAR/7Z 转换复用原有读取与安装保护，逐块检查取消并限制展开量；TAR 条目拒绝链接与特殊类型，名称沿用 safe_name。转换输出使用 ArchiveBuffer 限制为 512 MiB 的 Stored ZIP，交给原有校验、预览与解压预检；revision 始终根据源压缩字节计算。非 ZIP 禁止 pack/add/remove。TAR 根目录标记被忽略，PAX/GNU 元数据由 tar 库解析。转换会占用有界但较大的内存，当前不宣称流式低内存处理。

archive_operation 使用 directory_sftp 缓存，持有连接互斥锁保护整个操作。非 ZIP 单安全文件 <=2 MiB 的 list Reply.bytes 作为面板内预览快照，useArchiveController 仅在所选名称完全匹配时使用，刷新替换 listing；不用于 extract/add/remove/verify，原始摘要与重新读取校验不变。

ArchiveTree 缓存目录模型与祖先到真实名称的映射，滚动分批增加行，选择仍传后端真实 entry.name；不在前端解压。ArchiveEntryPreview embedded 模式复用 RemoteDocumentDialog，但不再建立嵌套 modal/focus trap；实际读取、取消和后端路径检查不变。

### 压缩包预览快照复用

打开压缩包后，只读预览复用当前面板的归档字节快照，切换新文件仅解码对应条目，不重复传输整个归档。后端使用 Arc 共享字节，全局 LRU 容量上限 128 MiB；空闲 120 秒的快照在下次缓存访问时清理。超过缓存上限的归档仍走有界读取，缓存淘汰后下次预览需要重新读取。前端保存已预览内容，Base64 字符总量上限 32 MiB，按最近使用顺序淘汰。缓存只在内存中，面板关闭及在途请求返回后释放，不写磁盘。

快照按连接、独立面板标识、路径和源摘要隔离。预览展示打开时的内容，外部修改后需要刷新；刷新会丢弃旧缓存。校验、解压、添加和删除仍读取源文件并保留原有摘要核对及覆盖保护，不能以预览快照替代真实源校验。未测量真实网络吞吐与端到端延迟，不承诺固定提速比例。

text_chunks.rs 提供只读偏移读取 IPC read_text_chunk；远程复用已验证连接的文件 SFTP，普通文件检查后 seek 并有界读取。本地使用 local_files::regular 拒绝链接入口。LargeTextPreview 持有解码器、偏移及大小/修改时间标记，单次请求串行，卸载后不更新状态。分块加载与 CodeMirror 可见行渲染分别控制网络读取和 DOM 开销，已加载正文仍占内存。

目录读取生命周期：前端 Promise 链保证每个工作区最多一个目录 IPC 在途，等待时过期的请求不发送。分页和流式列表均持有 Connection 锁完成读取，与共用浏览 SFTP 的预览串行；disconnect 通过独立 closed 标志发出停止信号，不等待该锁。目录失败清除缓存，不自动重试写操作。每个注册连接启动弱引用保活线程，每 5 秒尝试非阻塞获取连接锁并调用 keepalive_send（协议间隔 20 秒）；忙碌时跳过，断开或最后一个连接所有者释放后退出。调试日志只记录阶段耗时和成功状态。

ArchiveIo::copy_to 在连接锁内暂时切换非阻塞模式，属性、打开、读取和显式关闭均使用 network_step 等待 socket 就绪，并在重试间检查取消；作用域退出恢复原会话模式。保留逐级父目录、链接、读取期间大小变化检查与原有写入安装流程。performance.log 的 archive_stat/open/read/close 标记用于区分网络等待与后续解码，不记录文件内容或路径。

传输全程计时：前端创建 queued 任务时记录 timerStartedAt，所有阶段沿用该单调时钟，包括排队、扫描、暂停与收尾；终态保存 timerEndedAt，重试进入活动状态重新计时。队列存在未结束任务时每秒刷新；恢复的活动任务缺少开始时间则显示观察用时，历史终态缺失时间不伪造。该计时不持久化，扫描另显示阶段用时。

删除协议流水线：delete_requests.rs 在已验证且加锁的原 Session 上建立独立 SFTP v3 Channel，最多 16 个在途请求和 16 个目录句柄。目录重新 LSTAT 后 OPEN，READDIR 批次立即派发子项；每个句柄只发一个在途 READDIR，EOF 后确认 CLOSE 才记录待删目录。普通文件 REMOVE 按请求编号确认，支持乱序响应。全部请求成功后沿用分层 RMDIR。探测失败且未修改时回退旧队列，遍历开始后的失败不重放删除。路径名、深度、总条目和名称字节数边界保持；父路径检查及并发换名竞态仍存在。sftp_packet.rs 为删除与安装共享有界包读写，使用公开 Channel API；会话非阻塞模式由作用域恢复。

远程删除成功后前端立即移除服务器已确认的项目并关闭确认弹窗；废弃旧目录请求编号、清理页面缓存，再后台刷新当前页核对。后台结果不修改删除弹窗状态，避免覆盖下一次操作；失败和部分删除仍等待刷新并展示错误。完成提示计时到删除确认，delete_timing 日志另包含后台刷新时间。单文件路径检查报告检查删除路径，只有目录枚举才报告扫描目录。

单文件删除的 fileOnly IPC 提示仅限制能力：只做 UNLINK，目标变成目录时拒绝，不能以该提示进入递归。普通文件不再查询末级属性；统一 check_delete_path 保留真实父级 LSTAT 并跳过 POSIX 根目录，拒绝根目标、路径穿越和空字节。普通、递归与本地入口共享路径校验，删除命令统一一次获取连接锁及准备协议；目录删除工作函数只保留实际使用的 RMDIR 分支。delete_pipeline.rs 仍是额外 SFTP 子系统不支持时的可达兼容路径，不能作为死代码删除。

上传性能日志分别记录临时文件打开/续传、WRITE 确认、文件 CLOSE、安装和连接释放；每两秒记录确认字节数和在途请求数量，不记录文件路径或内容。上传速度每秒按已确认字节增量计算，排除建连、预检和暂停等待；总耗时日志使用 total，避免将包含建连和释放的时间误标为 data。每连接初始最多 2 MiB 写入请求载荷，自适应窗口最高 8 MiB；同任务文件共享连接预算，不含协议缓冲。

transfer_async_pool.rs 保存最多四个空闲上传连接。连接按主会话断开标志的 Arc 身份与完整信任指纹表匹配，租出后从池中移除，任务独占使用；不跨会话共享，不缓存凭据。仅成功且未取消的连接归还，失败不重放写入而关闭连接。主会话断开后，清理协程关闭 SFTP、目标与跳板；清理按唯一租约编号定位，不能关闭已经被另一任务租出的连接。已关闭或信任变化的连接不复用，下次建立连接仍先验证指纹。首次上传仍有握手成本；复用不保证服务器吞吐。

主会话连接和目录首屏成功后启动上传池维护协程，按传输并发设置后台预建 1～4 个可独占租用的原生异步传输连接。空闲连接不再一分钟过期，russh 的 15 秒 SSH keepalive 由目标/跳板协议驱动执行；每五秒检查空闲容量与已关闭连接，按配置连续补齐本会话的空闲连接，握手之间不额外等待；每个主会话最多保留四个空闲连接，预热计数包含建连中、租用中和空闲连接，不因任务租走连接而重复补建。主会话断开后清理协程在下一秒检查时释放池中连接。后台预建失败停止维护，避免重复认证或指纹失败；上传仍能显式建立连接。交互认证不后台预建，避免重复验证码提示；后台准备尚未完成时上传可按原路径独立建立连接。

上传预检按父目录深度分层查询：OPENDIR 明确返回 NoSuchFile 时，其后代父目录以缺失快照处理，不重复查询；权限不足仍逐项 LSTAT，不把权限错误当缺失。所有冲突预检通过后才写入，mkdir 创建竞态和不覆盖安装保持保护。同层 MKDIR 使用最多 16 个无句柄协议请求，仍等待父层完成。IPC 新增 connecting/prechecking/preparing 状态，分别显示准备连接、检查远程目标、创建目标目录；准备阶段字节仍为实际已确认上传字节，不伪造传输百分比。

transfer_schedule.rs 将 ≤256 KiB 上传文件独立调度，初始最多 8 个协程，每三秒根据文件完成率和平均生命周期评估；首次试探加四个，之后完成率提升超过 5% 且延迟涨幅小于 50% 才继续增加；完成率下降超过 15% 且延迟升高超过 25% 时减半。上限 32，服务器句柄预算优先；缩小只停止新增，不取消在途任务。大文件仍按原配置最多四个，至少 4 MiB 时跨连接写入；两组混合运行，活动文件总数遵守调度上限，每条连接另有共享句柄预算。请求正文、预读与等待预算的上界见下文上传流水线说明。文件错误仍停止整个任务派发，不为吞吐绕过校验或重放安装。日志记录 small_limit、active_small 和 active_large 供实际调节效果复核。

上传预检独立于大文件并发配置，使用最多 16 个查询/校验协程并遵守服务器句柄上限。目录查询只等待相关祖先，不设置整层屏障；确认缺失祖先后跳过后代查询。属性回退和已完成文件摘要校验并发执行，全部通过前不开始创建目标目录或上传。诊断记录目录请求与续传校验耗时、成功状态及失败阶段，不记录凭据或正文。

上传小文件队列交错领取较大与最小文件，空文件不集中留到尾段。每两秒依据完成率和生命周期评估，小文件健康并发按 8→16→32 探测，拥塞时减半，服务器句柄限制优先。上传剩余时间取文件安装完成率估算与字节速度估算的较大值，样本不足不显示预测；暂停清空采样，恢复后重新估算。此预测不是服务器完成时间承诺。

删除诊断按任务输出 parents/lstat/opendir/readdir/close/unlink/rmdir 的请求次数、总请求耗时与最大耗时，以及扫描/删除窗口峰值和独立墙钟总时长；日志不包含远程路径或文件内容。并发请求耗时互相重叠，不能相加解释为总等待时间。IPC 获取会话与界面刷新耗时分别记录。

开发构建的 `sftp_receive_trace.rs` 在 SSH 解密后的 SFTP 流边界记录 DATA 帧开始、接收完成和接收历时，仅输出协议编号和长度，不保存内容、路径或凭据。帧接收历时包括等待后续 SSH 通道数据与任务调度；不能单独据此判定服务器、网络或 SSH 解密耗时。配合归档 READ 总耗时区分首字节等待、整帧到达和原库解析/派发等待。正式构建不接入观察器。

`performance.rs` 在事件调用处采集时间，通过最多 1024 条记录的有界队列非阻塞投递，独立线程持有文件句柄并写盘、轮转和输出终端。队列满时丢弃诊断记录并汇总数量，不阻塞网络协程；退出时尚未写入的日志不保证持久化，日志不是业务完成依据。

Windows 归档 READ 批次另记录进程 CPU 增量（微秒），覆盖所有应用线程；结合响应首字节/接收历时判断计算忙碌还是等待，不能把其他并发应用任务的 CPU 全归因于单个 READ。其他平台记录不可用值。

下载多文件任务按配置租用连接组：小文件整文件轮转连接，大文件仍交错分片。新建传输连接在握手前注册生命周期令牌，成功后由连接持有，取消、失败或所有者释放时自动撤销计数。后台预热遵守每会话目标总数；并行前台任务仍可各自租用连接，不把每任务并发设置误作全应用连接硬上限。

生产下载完成记录通过最多 32 项队列交给作用域内持久化线程，每批最多 16 项、最长聚合 10 ms。落盘后才更新完成清单，下载终态等工作线程排空并确认结果；失败仍排空队列，避免生产者和收尾互相等待。写盘只合并已经到达的最多八块相邻范围，额外正文预算最多 1 MiB，不等待缺口，不改变源校验和失败裁剪规则。

下载每两秒按连接记录目标 SSH 密文输入字节、SFTP DATA 正文交付字节、处理进度及进程 CPU 增量。密文输入位于 TCP 读取之后、目标 SSH 解密之前；跳板模式位于 direct-tcpip 隧道内，不能视为外层 TCP 流量。协议头、压缩和缓冲使两个字节数不可直接比较比率；持续的层间停顿才用于定位，进程 CPU 包含其他线程。取消检查先于范围完整性判定，避免取消被显示为缺失范围错误。

原生 SSH 的直连和跳板外层 TCP 统一通过 transfer_tcp 建立连接：连接前请求 4 MiB 接收缓冲，连接后启用 TCP_NODELAY，并在 Windows 上通过 SIO_TCP_SET_ACK_FREQUENCY 请求即时 ACK。接收缓冲不等同于 SSH 窗口，也不保证线上 TCP 窗口大小；缓冲或 ACK 选项不支持时保留系统行为并记录结果，不修改注册表或全局网络设置。地址解析及逐地址回退保留，主机指纹验证仍先于认证。

多连接大文件下载共享尚未派发的范围，每条连接独立维持最多 64 个在途范围，再按完成顺序合流；迟到连接不会阻塞快连接补充请求，也不能挤占其他连接的额度。每条连接从 8 个请求起步，按刚完成请求从派发到收齐的耗时调整：低于 1 秒加倍，超过 4 秒减半但不少于 4 个，即每条连接约保留 1–4 秒自身吞吐量的工作。丢包或拥塞的连接因此只占少量范围，其余由先空闲的连接领取；已发出的 READ 不重放，慢连接手中已有的范围仍须由它收齐。单连接下载保持 64 个请求。

下载连接在读取中断开（如 russh keepalive 连续无回应后结束会话）时，只要该连接的 `Connection::is_closed()` 为真，它的在途范围整块改到下一条存活连接的句柄重新读取，调度端也不再给它分配新范围；服务器状态错误、短文件和取消不转交。转交请求不占目标连接的调度窗口，额外在途量不超过断开连接原有窗口。结束时只在存活连接上核对来源版本，至少一条确认通过；断开连接上的句柄随会话失效，跳过 CLOSE。之后的文件只在存活连接间轮转，主数据连接断开时属性查询改用存活连接。全部连接断开时返回带最后断开原因的“下载数据连接已断开”错误。传输连接通过 `Handler::disconnected` 记录第一次断开原因，keepalive 与无活动超时翻译为中文说明。接收端同时等待读取与写盘协程，按先失败的一方报告错误：读取先失败时不能被写盘端的“下载范围不完整”掩盖。四连接单文件最多 32 MiB 范围正文、8 MiB 写盘队列、8 MiB 摘要缓存及 1 MiB 合并正文，四大文件正文合计上限约 196 MiB，不含协议缓冲和分配容量。没有服务端读取限制声明时仍保留 32 KiB 兼容分片，已声明 limits 时最多 128 KiB。乱序正文超过摘要缓存时只写盘；连续写入前缀越过摘要位置后，从临时文件补读缓存之间的缺口，使摘要在接收过程中追上，不在结尾重读整段尾部。

下载续传预检仍对每个已完成文件重新计算远程和本地 SHA256，不因续传跳过校验。最多四个文件同时核对；远程摘要读取先取来源快照，使用下载分块，按偏移有序交付，至少 4 MiB 时跨下载连接交错读取，每连接 16 个请求。任一文件不一致即失败，其余在途读取被丢弃，失败的连接组不回池。

已完成上传文件的重试校验采用每文件 16 块有序预读、整个预检共享 64 个 READ 预算；本地校验与远端预读交错，并在读取前后检查文件大小和修改时间，完整核对本地与远端 SHA256。上传临时前缀也采用 16 块有序预读并逐字节核对；下载每连接独立请求窗口修复保留。

上传使用 transfer_upload_pipeline.rs：1 MiB 本地缓冲、64 块有界正文队列，读盘/摘要与网络发送由独立协程并行驱动；每连接字节预算初始 2 MiB、最高 8 MiB，总请求条数另外不超过 256，按两秒确认吞吐探测更大预算，扩大不足 10% 收益则退回前一个窗口。同一任务所有文件共享连接请求与句柄预算。大文件至少 4 MiB 时使用至多四条连接，数据范围不重叠，按平滑确认速率与排队请求数分配连接；小文件分配到不同连接。

跨连接写入前，将已验证的稳定 .part 关闭并移到带随机标识的独立暂存路径。记录 WRITE 成功确认的连续前缀，禁止把稀疏文件长度当作完成进度；派发位置最多超出连续前缀 32 MiB，限制确认范围缓存。成功必须收齐所有 WRITE 与所有连接 CLOSE，重新检查本地来源后才安装。失败只有所有 CLOSE 确认后，才能 SETSTAT 裁剪到连续前缀，再改名回稳定 .part 供重试；断线/关闭不明确的路径删除或隔离，后续任务从不按它的长度续传。已有目标在确认安装前保持完整。

上传未声明 limits 时保持 32 KiB，明确声明写入与包长度限制时，大文件最多使用 128 KiB，小文件仍不超过 32 KiB。每连接按 32 KiB 单位领取 2～8 MiB 字节预算，128 KiB 请求消耗四个单位；正文预读队列仍限制为 2 MiB，扩大分片不扩大内存上界。四连接请求正文预算最高 32 MiB；等待共享预算的协程和预读缓冲另有开销，四个同时调度的大文件的正文缓冲约有 140 MiB 上界，不含协议及分配器开销。首次握手和吞吐探测有成本，真实提速仍需用户服务器实测，不能据此承诺线性增长。

上传连接在目标与跳板握手时只协商 none 压缩；上传使用独立连接池，按主会话身份和信任指纹匹配，按需建立并在成功后归还，上传不能取回已有压缩连接，下载保留原压缩协商。窗口启动与切换后跳过一个预热样本，比较两个两秒样本的平均确认吞吐，稳定后约每 10 秒允许重新探测。逐连接记录确认速率、活动请求及 WRITE 确认平均耗时；该耗时包含 SSH 发送排队，不等同于 RTT 或远端纯写盘时间。关闭压缩对文本可能增加线上字节，真实收益需服务器实测。

大分片上传按连接限制的最小值处理，较小服务端上限优先；日志同时记录实际请求数、写块大小与字节窗口，不能将预算单位当作请求个数。

上传流水线按各连接平滑确认速率和排队请求数分配数据，保留每连接字节预算及连续前缀保护。窗口切换先等待旧预算下的请求全部确认，再预热和比较吞吐；已证明有收益的最大窗口不再定期减半。实际远端提速效果需要同文件实测。

上传 WRITE 确认后的进度按 256 KiB 或 100 ms 合并尝试上报；队列满时保留累计字节并继续补充网络请求，收尾时交付剩余进度。显示或检查点落盘变慢不会因进度队列直接阻塞上传正文流水线，最终字节数和安装确认顺序保持完整。

上传连接选择同时检查文件在途数和连接组共享字节预算。其他文件已占满某条连接预算时，优先把下一块派给仍有完整写块额度的连接，减少有空闲连接时的数据排队；最终预算仍由信号量领取，不突破内存上限。

上传连接在成功传输后保留经过吞吐对比验证的窗口；下一文件或任务复用这些连接时，从各连接自己的已验证窗口起步，并受当前共享预算限制。新连接从 2 MiB 起步，尚未验证的新探测窗口不保存，连接销毁后历史失效，不写入配置。

盘符菜单由按钮与 portal 弹层组成，不使用原生 select 或占位选项；菜单仅显示盘符、磁盘图标与当前选择标记。定位基于按钮视口坐标，避免面包屑横向滚动容器裁剪；外部点击、Esc、导航、窗口调整及外部滚动关闭，内部滚动保留菜单。支持方向键、Home/End，关闭时按操作恢复按钮焦点。

pending_transfers 必须提供当前 Profile，后端按 jobs 中保存的配置 ID、target 与 jump 精确过滤；不依赖重连后会变化的 connectionId。前端在进度订阅就绪、当前配置确定后恢复，各工作区分别加载；切换端点清空旧 ownedTransfers，异步恢复的迟到响应在 effect 清理后丢弃。历史记录保持持久化，重试及清理仍验证原端点。

上传专用 UploadTransport 在 AsyncWrite 成功接受字节时计数，Pending/短写不虚增发送量，读取沿用已填充字节差；跳板模式统计 direct-tcpip 内的目标 SSH 流，不改变下载适配器。WRITE 首次确认之前单连接只放一块，逐次确认后倍增至原窗口。WriteWatchdog 只在文件内实际进入 SFTP WRITE 的请求仍待确认时计时，任意成功确认、暂停或没有实际 WRITE 时重置；30 秒无确认触发 timeout 错误。失败后收齐 CLOSE 才能裁剪条带前缀，否则按原规则隔离/清理暂存文件，原目标不被替换。

download_pipeline 使用独立 WindowPolicy：普通 Transfer 从调用方完整窗口起步并保持该上限；携带源文件快照的无序预览达到 4 MiB 时使用 BulkPreview 保持完整窗口，小文件使用 Preview，保留从 8 个请求起步的自适应策略。ordered 打包路径沿用原窗口。read_plan 日志打印策略、初始及最大请求数量，避免把预览上限误认为实际在途数量。

archive_zip_remote 首次预取后解析局部头固定字段，以头长度加中央目录声明的压缩长度确定当前条目的预读边界；解码器小缓冲也维持最多 1 MiB 预读，尾部裁剪至条目结束。索引和条目外的读取沿用原策略。单批最多 32 个范围请求使用 buffer_unordered，按显式偏移填回预分配缓冲，已完成请求及时释放名额；每条响应仍检查空响应和越界，整批成功后才加入最多 2 MiB 的缓存，取消或失败不缓存部分正文。ZIP 库仍负责真实格式、CRC/AES 校验，读取后继续核对源属性。

普通连接池的 session_trust 只包含请求目标和跳板；主会话身份与这两个端点的指纹仍须匹配。take 和后台 maintain 先移除已关闭连接及同主会话过期信任快照，锁外异步关闭；不移除其他有效工作区的连接。预热明确统计 accepted/rejected，拒绝入池后等待 5 秒再重查，认证或指纹失败仍停止维护。沿用该池的小文件上传入口同步使用端点信任快照，上传专用连接池和写入管线不变。

connect IPC 返回已认证且 SFTP 就绪的 `{ id }`，不等待首屏目录；前端关闭认证弹窗后调用 list_remote_page，沿用目录请求序号及 connectionId 检查，迟到响应不得覆盖新会话。目录错误不撤销连接，无初始目录时刷新从 `.` 重试。普通 SSH 的目标私钥加载/解密通过 spawn_blocking 与握手 join 收齐，指纹校验成功后才认证；非 RSA 私钥跳过 best_supported_rsa_hash，RSA 保留原协商。private_key、handshake_and_key、authentication、sftp_channel、sftp_init、sftp_limits、ready 和 directory 分别记录耗时；并行阶段不可相加推算总耗时，不记录凭据。上传专用 SSH 实现保持原样。

remote_listing 对固定会话工作目录 `.` 与根目录 `/` 并行发送 REALPATH/OPENDIR，收齐后才使用规范路径构造条目；解析失败但 OPEN 成功时，至多等待 5 秒关闭该句柄。其他路径保持 REALPATH 成功后对规范路径 OPENDIR，避免额外引入符号链接变更引起的目录内容/路径不一致。READDIR、分页和正常 CLOSE 的行为不变。russh 的 request_subsystem 只将请求入队，并不额外等待远端确认；保留现有启动方式及服务端 limits 校验。

主会话保存 first_listing Notify，connect_session 调度 warm_after_first_listing 等待首个 list_remote_page 结束通知；通知可先于等待到达，成功或失败均放行。3 秒后仍无通知则回退到原预热策略，执行前重新检查 closed，断开不会启动后台握手；直接调用原 maintain_upload_pool 的入口不改变行为。

transfer_tcp 复用于普通和上传连接的新建 TCP 阶段：DNS 超时 10 秒，解析地址去重并交错 IPv4/IPv6，最多两个地址错峰 250 ms 尝试；明确失败立即补位，每个地址 15 秒，总预算含 DNS 为 30 秒。赢家返回即丢弃其余 future 与 socket，取消/超时同样回收，不在多个 TCP 连接上重复进行 SSH 认证。日志包含模块、dial_id、地址族及错误种类，不输出凭据。接收缓冲、TCP_NODELAY、Windows ACK 配置和已建立连接的数据读写参数保持原样。

### v0.4 同步与差异

`directory_sync_options` 在扫描前验证排除项，匹配目录后剪枝，两端使用相同语义。严格模式保留 SHA256；快速模式仅比较大小及已知秒级修改时间，缺失时间不视为相同。默认选项为严格且无排除项，原调用语义保持。`Difference.directory` 限制文本差异入口。`directory_sync_rules` 用独立 `sync-rules.json` 保存非敏感规则，进程内串行读取/更新，先写临时文件再安装；不改变连接配置格式。存储总量 4 MiB、每连接 20 条、100 个范围，解析失败不覆盖原文件；不提供跨进程写事务。

前端规则加载不导航或自动执行；修改比较设置会丢弃结果及选择。目录比较绑定根目录、连接 ID 和端点范围，变化或关闭时取消旧任务并拒绝过期结果。选择仍交给原 start_transfer 覆盖确认与临时安装流程。文本差异复用两个有界文本读取命令，关闭后忽略迟到结果；既有网络读取仍由原超时与会话关闭终止。行差异动态规划最多 250000 单元，更大中段采用替换，输入合计 6000 行。同步报告上下文仅在当前任务内存保存，事件更新保留上下文，报告展示真实任务状态而不推断逐文件成功；恢复历史任务不补造报告。

### 终端握手消息交错

`terminal::wait_request` 复用于 PTY 和 Shell 应答：只有 Success 确认完成，Failure/OpenFailure、EOF/Close/ExitStatus/ExitSignal 及通道结束明确失败。WindowAdjusted 是 russh 已处理的发送窗口通知，不能当作请求拒绝；其他通知继续等待。握手期间 Data/ExtendedData 共享最多 1 MiB 原始字节缓冲，成功后交付原输出循环。`Connection::terminal_channel` 限定 PTY/Shell 阶段 30 秒；失败路径有界关闭终端通道，保留共享 SSH/SFTP。日志只记时间、结果和缓存字节数，不记录终端正文。

### 终端视觉层拆分

工具栏固定为 32px，使用细下划线标识选中标签，保留 28px 工具按钮。终端显式禁用通用 header 的窄屏换行，标签区独立横向滚动；新增或切换标签时仅滚动至可见，不移动键盘焦点，不重建 SSH 通道。

`TerminalPanel` 管理标签、活动窗格、分屏、搜索与展开状态；`TerminalToolbar` 只显示工具栏并转发操作，样式显式覆盖旧 `.terminal-heading button` 的 auto 外边距。`TerminalSession` 持有原 xterm/PTY 生命周期，用 ref 发布握手状态及尺寸，单纯切换标签不会重建会话。搜索框在正文右上角按需挂载，Esc 仅关闭搜索并将焦点还给 xterm。新 `.terminal-session` 作用域补齐旧 viewport 背景和水平滚动条规则，避免旧 `.terminal-body` 选择器漏掉新结构。

界面验证使用 ignored 测试页导入生产组件及模拟 IPC，只验证显示与交互，不连接服务器；截图及模拟内容不能作为实际 SSH 兼容验收。

终端与日志区统一使用浅色背景、灰紫色边界和紫色交互状态。`terminalTheme.ts` 集中维护 xterm 的 ANSI 16 色、光标、选择区域与滚动条颜色，亮色文字也采用适合白底的深度；`minimumContrastRatio=4.5` 为正文提供最低对比度调整。仅修改呈现，不改变 SSH 字节流、会话调度或传输参数。

### 服务器工作台

`WorkspaceTabs` 持有共享的工作台偏好与串行连接追加队列；`workbench.json` 独立存分组映射和命令草稿，不改变 connections.json 格式。后端校验数量、文本长度、NUL 和未知字段，串行读改写并使用同目录临时文件替换；旧文件损坏时拒绝覆盖。`connectionBundle.ts` 只导出白名单字段，导入拒绝未知字段并重新分配 ID，不携带主机信任，合并复用原 save_profiles 校验和串行队列。

`ServerWorkbench` 按需加载；`ServerMetrics` 只有用户启用且会话可见时串行采样，关闭/切换取消后续定时器并忽略过期结果。`server_metrics` 固定执行 Linux 只读脚本，按 /proc/stat 两次计数差计算 CPU，MemAvailable 计算内存，df -Pk / 读取根分区。`workbench_command` 仅接受显式确认的完整命令，通过原已认证连接建立独立 exec 通道，不申请 PTY、不拼接文件路径、不解析插值、不自动重试。命令正文和输出不写性能日志。通道建立最多 10 秒，发送/接收最多 15 秒，输出 stdout/stderr 合计 64 KiB（按到达顺序合并）。关闭通道最多等待 2 秒；超时或断开不能保证远端进程停止，界面显示结果未知。全局最多 3 个工作台请求，不修改上传/下载连接池、窗口或调度。

### 多格式归档写入

`archive_encode.rs` 集中校验可写格式、压缩等级与密码约束。ZIP 继续用原 ZipWriter + 有界远程预读；TAR/7Z 先用同一来源流水生成受限 Stored ZIP，再以 tar/flate2/bzip2/xz2/sevenz-rust2 编码实际格式。没有调用外部进程。各层输出均使用 ArchiveBuffer 在每次写入和 seek 前限制 512 MiB；单条目解码检查取消、声明大小和 CRC。7Z 使用非固实单线程 LZMA2、8 MiB 字典，可选 AES-256 与加密文件名。TAR 头部标准化 UID/GID、mtime 与 0644/0755 权限，不保留原特殊元数据。

非 ZIP 重建复用原解码器、路径和膨胀校验，重写前校验列表版本，安装前再次读取原始字节计算摘要；完成编码后才进入原 ArchiveIo.install 临时安装/恢复流程。旧 ZIP 的保留项默认 raw_copy；提供密码时校验原加密条目并重编码所有保留文件，新增条目也用同一 AES 选项，密码不会保存到进度事件或快照。非 ZIP 编码前释放原归档解码器，TAR 外层压缩前释放中间 ZIP，减少同时驻留的缓冲。

`archiveCapabilities.ts` 管理前端格式选择、后缀转换和只读提示；后端独立按格式校验。格式切换清除不支持的密码和压缩选项；修改后重新列表保留当前读取密码，避免加密 7Z 重建成功后无法重开。PackProgress 新增 encode 阶段；非 ZIP 中间缓冲不计入 zipBytes，直到目标格式编码结束才显示最终字节数。上传下载调度与连接池未改变。

## 已授权的批量权限加速边界

批量权限加速曾获用户明确授权，对 AGENTS.md 第 4 节“后台文件操作不使用 shell”的默认约束作范围内例外：只执行固定权限脚本，不使用 eval，不接受用户命令，不安装或上传执行文件。能力不足或 exec 禁用时，仅在尚未修改前回退 SFTP；开始修改后不自动回退或重试，失败可能已部分修改，需刷新核对。此例外不扩展到任意后台文件操作，脚本存在不等于真实 Linux/macOS 端到端与性能验收通过。

## 上传完成后的提交与续传保留

多连接条带写入只有所有 WRITE/CLOSE 已确认、源大小和修改时间核对通过，才恢复稳定 `.part` 名并执行安装；改名后再次核对源。安装失败保留完整稳定临时文件，后续重试核对完整前缀，不重新发送已确认正文。恢复稳定名失败时保留独立暂存内容并在界面提示核对路径，不把未知布局当作可续传前缀；显式取消仍由任务协调器按 touched 集合清理。

两条原生上传安装路径在覆盖前核对临时文件普通类型、长度与权限，权限已相同时不重复 chmod。仍需修改权限而服务器拒绝时不得静默忽略。`install_stage_error` 保留 AppError 内部标志，仅增加固定提交步骤，性能日志不记录路径和原始服务端正文。目标安装后仅备份清理失败时明确报告已安装状态及备份位置，不报告成正文未传完；前端诊断摘要只导出固定阶段白名单。

`transfer_atomic_replace` 由两条上传路径共用。服务器声明支持 POSIX 改名时，先用 lstat 保存源和目标的普通文件属性；明确返回“不支持”或通用 `FAILURE` 后，只有两端仍存在且长度、权限、属主与修改时间均未变化，才进入既有备份改名与失败回滚流程。权限拒绝、超时、断线、异常响应及状态变化均停止，不先删除旧目标。属性复核不提供跨客户端事务，也不能识别同大小同时间戳的内容改写；该兼容处理不等于已确定任一真实服务器的拒绝原因。

## 阅读记忆、恢复提示与本地容量预检

`epubReadingState.ts` / `useEpubReadingMemory.ts` 使用完整 EPUB 的 SHA256 作为本机阅读键，在 `termrill.epubReading.v1` 保存最多 50 条章节序号、章内滚动比例与字号；不保存路径、标题、锚点或正文。内容解析与摘要的异步结果在卸载/换书后丢弃，恢复完成前不写初始第一页，图片布局变化只在用户尚未主动导航时补偿。400ms 合并滚动写入，pagehide 和卸载提交最后有效快照；异常记录不被覆盖，存储失败不阻断阅读。

`transferRecoveryHint` 说明现有的显式认证/重连约束；其他未结束任务包含暂停状态，无连接且重连受阻时禁用续传按钮。不会由休眠、网络事件或错误文本自动启动认证、断开共享会话或重放文件操作。

`local_space.rs` 在阻塞线程查询本地下载临时文件父卷的用户可用容量（Windows GetDiskFreeSpaceExW / Unix statvfs），接收正文前只核对源长度减已有连续前缀；容量不足不修改旧目标或已有前缀。预检不是容量预留或跨任务事务；配额、稀疏/压缩与并发写入仍以实际写入结果为准。不查询或猜测远程空间。

### 显式跨进程恢复验收

`process_recovery_tests.rs` 仅在库测试中编译，通过显式阶段变量使用临时配置与任务清单；`tests/process_recovery.py` 控制准备/强退/恢复/移除阶段，每次使用新进程重新加载生产任务日志，检查认证前没有缓存连接。下载与指纹验证复用原生生产流程，移除调用同一清理入口；不改变运行时存储格式、网络设置或应用标识。单条数据连接用于稳定复现连续前缀，完整长度与 SHA256 在父进程核验；普通回归不自动强制结束进程。

### 显式授权服务器对照边界

`server_benchmark_tests.rs` 仅在库测试构建存在，阶段清单限制来源为本次随机测速目录内的固定文件，输出目录必须位于本仓库专用运行目录并匹配同一随机标识。正式应用不读取测速清单或诊断参数。`tests/server_benchmark.py` 需要明确配置 ID、已信任指纹和远端写入授权标志；通过 SFTP 独占创建并清理 8 MiB 随机内容，不执行远端 shell。持久化记录采用白名单字段，私钥内容与口令不进入清单；公开输出不含地址、账号或远程路径。失败保留私密清理记录，成功只移除本次固定文件和空目录。
